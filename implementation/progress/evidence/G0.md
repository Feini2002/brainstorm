## 2. 生产启动实测（scripts/start-local.mjs）

隔离数据目录与端口，避免触碰用户 `.data`：

```powershell
$env:BRAIN_DATA_DIR="$PWD\.tmp-probe-data"; $env:APP_HOST="127.0.0.1"; $env:APP_PORT="3199"
$env:APP_ORIGIN="http://127.0.0.1:3199"; $env:NODE_ENV="production"
node scripts/start-local.mjs start
```

观察到的输出：

```
▲ Next.js 16.3.5
- Local:         http://127.0.0.1:3199
- Network:       http://127.0.0.1:3199
✓ Ready in 135ms
✓ Running next.config.ts took 42ms
```

结论：production build 能在本机回环地址启动并进入 Ready。该进程由外部超时终止
（运行 98s 后被 kill），不是服务自身崩溃。收尾核验：端口 3000/3199 无监听残留，
无 `node` 进程残留，`.tmp-probe-data` 已清理。

### 5.4 从被删套件并入 `security-http.test.ts` 的独有断言

下列 4 条在另一套里没有等价断言，删除会丢覆盖，因此并入保留套件（沿用该文件既有的
`rawCall` / `callRoute` / `failureCode` 与命名风格），并逐条做了变异验证确认它们会真的失败。

| 并入的断言 | 挡住什么真实旁路 | 变异验证 |
| --- | --- | --- |
| T007-R03 私人 GET 不要求 Origin，但令牌始终必需 | 表单/图片式请求没有 Origin 可伪造；T007-R03 明文允许缺 Origin，若同时不要求令牌，旁路立刻成立。反面还断言：Origin 一旦出现就必须精确匹配，读取路径没有第二次匹配机会 | — |
| T007-C01 mutation 拒绝显式跨站的浏览器元数据（含错误文案） | 攻击者若在受害者页面凑出正确 Origin 与令牌，`Sec-Fetch-Site` 是最后一道元数据判据；断言独立错误码可防止将来放宽 Origin 比对时这道防线静默消失 | 删除 `guardBootstrap` 与 `guardMutation` 两处 `cross_site` 判定 → **1 失败 / 17 通过** |
| T007-C02 Host 判据是「回环地址 + 端口」精确匹配 | 只比对主机名会让「端口不同＝另一个来源」漏过去；`127.0.0.1.nip.io` 代表解析到回环地址的公开域名，正是 C02 要排除的「按 IP 连上了就放行」 | 把 `checkHost` 放宽为「精确匹配或前缀匹配 `127.0.0.1`/`localhost`」→ **1 失败 / 17 通过** |
