## 5. 本轮修掉的真实缺陷（产品代码）

### 5.1 契约守卫用例会随进度静默失效（T012-C06）

`tests/contracts/guard.test.ts` 的 T012-C06 把 `/api/export` **写死**成「尚未实现的端点」，
并在替换前断言这个前提成立。T070 一旦落地，该前提为假，**用例直接红**。

这不是新问题：用例自己的注释就记录了同一个坑——它更早写死的是 `/api/graph`，
G3 实现该路由后那句替换不再命中、用例**静默失效**过了。也就是说这个用例有
「实现一个契约端点就红一次，或者悄悄不再断言」的结构性缺陷。

**修法**：改成从 `PENDING_ROUTES` **动态**挑一条仍然没有 `route.ts` 的端点来删，
于是用例随进度自然迁移，不会再因为某个具体端点被实现而失效或空转。

```
npx vitest run --project contracts tests/contracts/guard.test.ts  →  7 passed (7)
```

### 5.2 lint 残留（1 warning → 0）

`tests/integration/flow-history.test.ts` 的双替身 `async send(_request: TransportRequest)`
与随之无用的 `TransportRequest` 导入造成 2 条 `no-unused-vars` warning。
改为更短签名 `async send()`（TypeScript 允许实现省略参数）并删掉无用导入。

```
npm run lint  →  exit 0（0 problems）
```

### 5.3 T073 损坏库断言的机制写错了

我最初断言损坏库时 `readable: true` 且 `integrity: 'damaged'`。实测发现：
带合法头部的损坏文件会被 SQLite **接受打开**，但一执行查询就抛错，
于是脚本报 `damaged` 而 `readable` 为 `false`。原断言与真实机制相反。

**修法**：改为断言 `integrity === 'damaged'` 且 `integrityDetail !== null`、
退出码为 `EXIT.damaged`。仍然**不做**「damaged 或 unreadable 都接受」的松断言——
那会让「脚本根本没打开文件」也蒙混过关。

### 5.4 诊断面板把「重新检查」按钮放进了被测量的盒子里（T074）

T074-C03 的 e2e 第一次运行失败，报 Playwright 反复重试点击
`diagnostics-recheck` 而 `<section>` / `<header>` 拦截了指针事件。根因不是测试写错，
而是**产品组件结构错误的真实体现**：

被测的盒子就是整个面板外层 wrapper，而「重新检查渲染尺寸」按钮也在这个 wrapper 里。
e2e 把 wrapper 压成 `height: 0; overflow: hidden` 之后，按钮自己也被隐藏了——
即面板唯一能解释「页面为什么空白」的交互入口，被它自己要报告的那个条件挡住了。
用例的 unit 侧断言（`assessRenderSurfaces`）全绿，所以这条只有真实浏览器能发现。

**修法**：把测量面与外层 wrapper 拆成两个盒子。`data-testid="diagnostics-surface"`
是被测量的内容区；外层 wrapper 不参与测量，因此按钮始终可点。这不是为了让测试通过
而放宽断言——断言（「高度为 0 必须报渲染尺寸问题」）一个字没改，改的是产品结构。
已在 T074-7 第 5 条登记为下游必须保持的约束。

## 7. 已确认的安全边界（实测，不是设计意图）

- **导出产物不含秘密**：`exportKnowledge` 用显式白名单列（`BACKUP_*_COLUMNS`）而不是
  `SELECT *`，并由 T070-C02 的扫描用例 + 3.1 的变异实验双重确认。
- **恢复不导入秘密也不覆盖目标**：T072-C04 断言目标的 `settings` 与 `secrets` 在恢复后
  与恢复前逐字节一致；T072-C04 同时断言 Run 表不被写入。
- **恢复不触发模型**：T072-C05 断言恢复过程零模型调用——这条比「没有请求」更强，
  它断言的是**不产生 Run 记录**，因此连「打算调用但失败了」也排除在外。
- **诊断脚本只读**：3.4 的变异实验证明「改成可写就会被抓到」，且还原后
  `recovery.test.ts` 用检查前后 SHA256 相等来保证只读。

## 8. 需要下游知道的交接点

1. **`BACKUP_SCHEMA_VERSION = 1`**（`src/domain/exportBundle.ts:51`）。恢复侧
   `validateBundle` 对未来版本**明确拒绝**而不是猜测兼容（T071-C01）。改这个常量
   必须同步改 `importBundle.ts` 的版本分支和 T071-C01 用例。
2. **导出上限 `exportBytesMax = 20971520`（20 MiB）** 已登记在
   `reference/contracts/limits.json` 与 `src/domain/limits.ts` 两处，契约检查会比对两者。
   只改一处会导致 `npm run contracts` 失败。
3. **恢复路由的请求体上限走 `bodyLimit: 'import'`**（`src/server/http/respond.ts` 的
   `ROUTE_BODY_LIMITS` 按路由族区分），不是全局默认值。新增同类大体积端点应复用这个 kind。
4. **`inspect-data.mjs` 是 `.mjs` 而不是 `.ts`**，故意的：它必须能在**没有构建**、
   没有 TypeScript 的机器上直接跑，否则「数据库坏了但服务起不来」时它就没用了。
   因此它不参与 `tsc` 类型检查，改动后请用 `tests/integration/recovery.test.ts` 兜底。

## T074-3. 日志保留与轮转的设计选择

**能轮转的是什么**：诊断日志目前的 sink 是**进程标准输出**（`retention.sink = 'stdout'`），
所以「轮转」在这里不是翻文件，而是两条可核对的界：

1. **保留上限**：`diagnosticJournalCapacity`（200）条。FIFO，超出即丢最旧一条，
   计数记在 `journal.droppedByRetention`。内存里最多 200 条事件，不随运行时间增长。
2. **重复限流**：`diagnosticRepeatLimit`（3）次 / `diagnosticRepeatWindowMs`（60000 ms）。
   同一 `(code, route, requestId)` 键在窗口内最多打印 3 次，之后只累计
   `journal.suppressedRepeats`，不再打印整条记录——所以「每秒一次的临时错误」
   不会每秒刷一屏堆栈。

**为什么不做文件轮转**：本版本不写日志文件（AGENTS.md 的范围约束里没有日志文件需求，
而写文件会引入路径、权限与磁盘耗尽面）。把 sink 声明为 `stdout` 是**如实报告**而不是
省略：用户能据此知道日志由宿主/终端负责留存，而不是我们假装已经轮转过文件。
三处上限值同时登记在 `reference/contracts/limits.json` 与 `src/domain/limits.ts`，
由 `npm run contracts` 比对；`retention` 整块也在响应里回给用户核对。

## T074-7. 需要下游知道的交接点

1. **`/api/diagnostics` 是私有路由**，走 `createRouteHandler({ route: 'diagnostics.read' })`

2. **`DiagnosticsReport` 的字段是白名单**（`src/domain/api.ts`）。想加字段必须同时

3. **`dataDir` 故意只有 `{kind, exists, writable}`**，没有 path 字段。要显示路径是

4. **`telemetry: 'none'` 是结构声明**：本模块没有任何出站调用。若将来引入任何第三方
   SDK，`T074-R03 / C06` 会红——这个张力是有意的。
5. **测量面与它的控件必须分属两个盒子**（`diagnostics-surface` vs 外层 wrapper）。

- 重定向被归类为 `PROVIDER_NETWORK`，**让用户去查网络和防火墙**，而服务商其实已经答复了；
- `mayHaveBeenBilled()` 返回 true，对一次**从未离开本机**的请求宣称「可能已计费」。

修复：新增 `errorChainText`（有界遍历 `cause` 链，深度上限 5，防病态环）与
`REDIRECT_REASON` 短语匹配。用的是**短语而不是裸词** `redirect`：DNS 失败的 cause 里含
主机名（`getaddrinfo ENOTFOUND redirect.example.com`），裸词会让一个主机名恰好含 "redirect"
的 Base URL 被误报成重定向——正是这次要修掉的那类误诊。

### 一个真实用例缺陷：备份计数断言写死 `条目 1`，只在单跑时成立

`backup-restore.spec.ts` 的 T078-C01 最初断言校验报告写着 `条目 1` / `视图 1`。单跑该文件时它是绿的
（库是空的），**放进全量就红了**：

```
Expected substring: "条目 1"
Received string:    "校验通过。备份内容：条目 454 · 标签 6 · 标签连接 309 · 关系 96 · 视图 77"
```

根因不是产品：备份是**整库**快照，全量跑时共享库已被前面几十个 spec 写入几百条，计数当然不是 1。
写死数字的用例其实在依赖"上一个 spec 没留下数据"——正是 T078 要排除的跨场景耦合。

修法：断言改成"**界面报的数 = 这份备份字节里的数**"，即先从导出的 JSON 里数出
`knowledgeItems/tags/itemTags/relations/views` 的长度，再逐项比对界面文本；另加"至少含刚种下的那一条"
作为非空下限。这样单跑与全量都成立，而且比原来的断言更强——它验证了计数**真的来自这份备份**。

顺带发现两个断言细节：`标签 6` 会被 `标签连接 309` 前缀误匹配，所以带上分隔符 `标签 ${n} ·`
才是有意义的断言；这类"看起来对了"的子串断言错了不会报错，只会永远为真。

### 一个真实装置缺陷：`consoleWatch` 把用例自己的断网制造当成未捕获错误

T078-R03 要求全局监听后，先前"全绿"的 `T025-C02` **红了**。根因不是产品：该用例主动
`route.abort('connectionreset')` 丢掉自己的第一次 POST 来制造"响应丢失"，浏览器照例把
`net::ERR_CONNECTION_RESET` 打到 `console.error`。

处置：在 `consoleWatch.ts` 增加**第三条**豁免规则，且要求该用例另行断言"重试成功、两次请求键相同"——
豁免的是**已知会发生的那条消息**，不是让用例免于断言。没有引入 `page.on('pageerror', () => {})` 式全局屏蔽。

这正说明"全局监听从不开"不会自证有效：装置开启前 121/1 全绿，开启后才逼出这条分类问题。

### 一个真实装置缺陷：IME 用例曾**空过**

`narrow-and-ime.spec.ts` 的输入法用例最初用 `input.press('Enter')`。Playwright 的 `press` **不设置
`isComposing`**，所以 `shouldSubmitFromKeyboard` 里的组合守卫即使被删掉，用例依然全绿——断言没落在
它声称要保护的那条路径上。

修法：改为 `page.evaluate` 派发带 `isComposing: true`（及 `ctrlKey: true`）的真实 `KeyboardEvent`，
与"组合已结束"的 `isComposing: false` 构成对照。差别是**可观测的**：派发原生 `key: 'Enter'` 会让浏览器
插入换行，因此断言从 `toHaveValue(text)` 改为 `toHaveValue(text + '\n')`——这个换行本身就是"事件确实到了
DOM"的旁证。
