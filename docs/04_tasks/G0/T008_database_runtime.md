# T008｜数据路径、连接与文件生命周期


任务编号：**T008**。所属阶段：**G0｜基础环境与安全存储**。状态：**待实现**。这是实施规格，不是已经执行的测试报告。

## 一、目标与用户可见结果

保证所有页面和任务始终访问同一个明确的数据库，并能在重启、热更新、测试隔离和路径异常下保持可解释的行为。

该任务负责的是“SQLite结构、事务与持久化”。合格实现不仅要在正常样例上工作，还必须守住这里规定的不变量。它不授权扩大MVP范围，也不授权替换整个技术栈。功能完成以后，应能通过本任务验收文件独立判断，而不是依赖实现者口头说明。

## 三、输入与输出契约

**输入：** BRAIN_DATA_DIR、当前工程根、运行模式、临时测试路径。

**输出：** 按绝对路径缓存的DB连接、WAL配置、只在运行时初始化的目录、可注入数据库工厂。

本任务允许：执行参数化查询、版本条件更新、外键约束和DTO解码。边界以外：不得在事务中等待网络、自动删库重建或把同一知识存两套权威格式。输入来自外部时先验证，内部状态只由该层合法操作修改。字段名、枚举、数量限制和版本行为以规范契约为准，不依据UI文案自行创造另一种类型。

## 五、必须逐条落地的规则

### T008-R01

默认路径为项目根.data/brain.db；允许显式BRAIN_DATA_DIR，但路径只能由进程配置提供，不能由普通API请求决定。

### T008-R02

第一次真正请求数据库时创建目录，不在import或build阶段创建；全局单例按绝对路径区分测试库。

### T008-R03

启用foreign_keys、WAL和busy_timeout，检查实际返回值；不能只执行PRAGMA就假定生效。

### T008-R04

开发热更新复用同一进程缓存，测试结束显式关闭连接；不得每次请求都打开关闭导致连接抖动。

### T008-R05

连接异常时不自动删除数据库重建，权限失败、损坏、版本过高都需要明确错误。

### T008-R06

文件库不要放网络盘或同步中的云盘目录；备份与搬迁有独立操作说明。

## 六、装配顺序与局部实现策略

第一步确认前置输出已经可读取，列出本任务实际要消费的字段与函数。不要先画完整界面再发现上游没有需要的版本或ID。第二步在责任层实现核心转换或操作，先用最小输入验证成功分支，再加入边界输入和错误分支。

第三步连接上下游：上游Service以事务包裹仓储；下游是单一SQLite文件，DTO出库后供UI和模型流程共享。第四步把状态变化和错误反馈接到实际使用入口，明确何时允许用户再次操作。第五步运行本任务的正常和反例用例，复核不应发生的副作用，而不是只观察表面结果。

最后执行与本任务相关的类型检查、单元或集成测试，并在必要时跑浏览器。局部实现通过后再执行上一个Gate的冒烟回归，防止共享模块改动破坏已经可用的采集与数据路径。

## 七、状态、错误与一致性检查

重点观察：目标表、关联表、约束、user_version与连接生命周期。在测试前记录基线，在测试后比较目标变化与未授权变化。发生错误时必须遵循统一错误协议，不能把异常吞掉后返回空成功，也不能用随机重试掩盖不确定的提交状态。

关键负向要求：没有悬空引用、半事务提交或用户数据库污染；相同请求不造成重复实体。内存替身不能替代此用例的关键断言；需要文件库证明路径、锁和重开行为。若当前任务涉及外部依赖，不可用时给出明确降级或阻塞说明；无需外部依赖的部分仍应保持可用。

## 八、验收、证据与恢复

本任务有6个具名验收场景，详见独立用例文档。执行观察方式：在真实临时文件库执行并检查行数、主外键、版本与事务回滚；关闭重开后再次读取。验收证据包含实际输入或最小fixture、动作、预期与实际结果、命令退出码、相关实体ID或版本以及失败定位。

清理与恢复：关闭所有测试连接，检查WAL相关文件后仅删除临时目录，不触碰应用真实.data。没有执行的用例只能标为未执行或环境阻塞。使用测试替身的结果不得写成真实外部服务已经通过；模拟的成功响应也不能出现在正式产品中冒充功能。

## 九、交接给下一个任务

交接时说明新增公开函数、DTO或组件的名字，列出已验证规则和仍阻塞的事项。不要把实现细节藏在临时聊天记录里。后续任务只应依赖本任务稳定输出，不应读取私有内部状态或复制SQL。改变契约必须同步其权威文件和所有受影响用例。

完成标准是：规则有实现位置，用例有执行证据，错误有可恢复路径，共享数据没有新增歧义。不能用“页面已经画出来”代替这个标准。
