# T004｜启动脚本、回环监听与退出


任务编号：**T004**。所属阶段：**G0｜基础环境与安全存储**。状态：**待实现**。这是实施规格，不是已经执行的测试报告。

## 一、目标与用户可见结果

提供 Windows 与常见终端均可使用的本机启动方式，明确开发模式与日常生产模式，防止默认监听所有网络接口。

该任务负责的是“运行环境与工程配置”。合格实现不仅要在正常样例上工作，还必须守住这里规定的不变量。它不授权扩大MVP范围，也不授权替换整个技术栈。功能完成以后，应能通过本任务验收文件独立判断，而不是依赖实现者口头说明。

## 三、输入与输出契约

**输入：** 已锁定依赖、应用端口配置、启动参数和环境变量。

**输出：** dev、build、start、lint、typecheck、test 脚本以及实际监听验证方法。

本任务允许：读取命令版本、解析工程路径、验证依赖和启动方式。边界以外：不得读取真实笔记、调用模型或修改用户全局系统配置。输入来自外部时先验证，内部状态只由该层合法操作修改。字段名、枚举、数量限制和版本行为以规范契约为准，不依据UI文案自行创造另一种类型。

## 五、必须逐条落地的规则

### T004-R01

dev 与 start 显式传入 --hostname 127.0.0.1；文档统一访问 http://127.0.0.1:3000，不把 localhost 与回环 IP 随意混用。

### T004-R02

端口改变时 APP_ORIGIN 与 CLI 端口必须一起更新；采用单个 Node 启动包装器解析配置，避免 Windows 环境变量语法不兼容。

### T004-R03

生产模式先 build 再 start；不设置 output:export；本机 API 和 SQLite 需要 Node 进程持续运行。

### T004-R04

lint 显式运行 ESLint CLI，typecheck 显式运行 TypeScript；不能依赖框架 build 顺带做所有检查。

### T004-R05

启动包装器转发退出信号并保留正确退出码，禁止不断自动重启掩盖启动失败。

### T004-R06

端口占用时提示已有实例或端口冲突，不自行选择随机端口后让 Origin 校验失配。

## 六、装配顺序与局部实现策略

第一步确认前置输出已经可读取，列出本任务实际要消费的字段与函数。不要先画完整界面再发现上游没有需要的版本或ID。第二步在责任层实现核心转换或操作，先用最小输入验证成功分支，再加入边界输入和错误分支。

第三步连接上下游：通过package脚本被后续所有任务使用；环境报告提供事实，不承担业务成功判断。第四步把状态变化和错误反馈接到实际使用入口，明确何时允许用户再次操作。第五步运行本任务的正常和反例用例，复核不应发生的副作用，而不是只观察表面结果。

最后执行与本任务相关的类型检查、单元或集成测试，并在必要时跑浏览器。局部实现通过后再执行上一个Gate的冒烟回归，防止共享模块改动破坏已经可用的采集与数据路径。

## 七、状态、错误与一致性检查

重点观察：项目脚本、配置和临时探针文件。在测试前记录基线，在测试后比较目标变化与未授权变化。发生错误时必须遵循统一错误协议，不能把异常吞掉后返回空成功，也不能用随机重试掩盖不确定的提交状态。

关键负向要求：没有新增模型调用，没有修改真实.data，未改变全局registry或证书配置。尤其检查失败退出码是否非零、错误是否定位到真实前提，不允许脚本捕获异常后仍返回成功。若当前任务涉及外部依赖，不可用时给出明确降级或阻塞说明；无需外部依赖的部分仍应保持可用。

## 八、验收、证据与恢复

本任务有6个具名验收场景，详见独立用例文档。执行观察方式：记录执行命令、退出码、实际解释器路径与生成文件列表；对文件操作比较目录前后快照。验收证据包含实际输入或最小fixture、动作、预期与实际结果、命令退出码、相关实体ID或版本以及失败定位。

清理与恢复：关闭本用例启动的进程，只删除本用例临时文件，保留原锁文件用于复核。没有执行的用例只能标为未执行或环境阻塞。使用测试替身的结果不得写成真实外部服务已经通过；模拟的成功响应也不能出现在正式产品中冒充功能。

交接时说明新增公开函数、DTO或组件的名字，列出已验证规则和仍阻塞的事项。不要把实现细节藏在临时聊天记录里。后续任务只应依赖本任务稳定输出，不应读取私有内部状态或复制SQL。改变契约必须同步其权威文件和所有受影响用例。
