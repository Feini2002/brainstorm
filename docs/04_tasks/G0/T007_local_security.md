# T007｜本地请求令牌与来源防护


任务编号：**T007**。所属阶段：**G0｜基础环境与安全存储**。状态：**待实现**。这是实施规格，不是已经执行的测试报告。

## 一、目标与用户可见结果

在没有用户登录的前提下，避免其它网页直接读取本机笔记或替用户调用付费模型；保护的是本机浏览器边界，不是假装实现多人身份认证。

该任务负责的是“本机请求与不可信内容边界”。合格实现不仅要在正常样例上工作，还必须守住这里规定的不变量。它不授权扩大MVP范围，也不授权替换整个技术栈。功能完成以后，应能通过本任务验收文件独立判断，而不是依赖实现者口头说明。

## 三、输入与输出契约

**输入：** 请求Host、Origin、Sec-Fetch-Site、方法、进程内随机令牌与受信APP_ORIGIN。

**输出：** 受控会话引导、所有私人API的请求保护、无跨域授权的响应、重启后令牌刷新逻辑。

本任务允许：验证来源和令牌、限制出站目标、净化非React标记、清除秘密。边界以外：不得以可用性为理由关闭所有保护，或承诺防住已控制操作系统的攻击者。输入来自外部时先验证，内部状态只由该层合法操作修改。字段名、枚举、数量限制和版本行为以规范契约为准，不依据UI文案自行创造另一种类型。

## 五、必须逐条落地的规则

### T007-R01

Host必须与配置的回环地址和端口精确匹配，不能信任任意X-Forwarded-Host；代理部署不在范围。

### T007-R02

进程启动生成随机令牌，仅由受保护同源session接口返回；前端保存在内存，后续通过X-Brain-Token发送。

### T007-R03

变更请求要求Origin匹配且令牌有效；私人GET也要求令牌，防止通过图片或表单式请求旁路。

### T007-R04

session引导不开放CORS，不接受明确cross-site请求；无浏览器元数据的本机自动化需要按测试契约提供显式Origin。

### T007-R05

令牌比较使用安全方式，错误信息不区分猜中了多少字符；服务重启后前端只重取令牌，不自动重放付费操作。

### T007-R06

同源恶意脚本和已控制操作系统的进程不在此防线保障范围；这仍不是可以暴露给局域网的认证方案。

## 六、装配顺序与局部实现策略

第一步确认前置输出已经可读取，列出本任务实际要消费的字段与函数。不要先画完整界面再发现上游没有需要的版本或ID。第二步在责任层实现核心转换或操作，先用最小输入验证成功分支，再加入边界输入和错误分支。

第三步连接上下游：所有敏感API共用同一guard，所有外部请求共用endpoint策略，Renderer只接受净化后受控数据。第四步把状态变化和错误反馈接到实际使用入口，明确何时允许用户再次操作。第五步运行本任务的正常和反例用例，复核不应发生的副作用，而不是只观察表面结果。

最后执行与本任务相关的类型检查、单元或集成测试，并在必要时跑浏览器。局部实现通过后再执行上一个Gate的冒烟回归，防止共享模块改动破坏已经可用的采集与数据路径。

## 七、状态、错误与一致性检查

重点观察：来源校验结果、秘密可见性、出站调用计数及受保护数据。在测试前记录基线，在测试后比较目标变化与未授权变化。发生错误时必须遵循统一错误协议，不能把异常吞掉后返回空成功，也不能用随机重试掩盖不确定的提交状态。

关键负向要求：被拒绝行为没有写入和付费副作用，秘密标记不进入任何公开或可分享产物。测试恶意输入不能真的访问未知外部域名；使用受控测试端点或transport记录意图后拦截。若当前任务涉及外部依赖，不可用时给出明确降级或阻塞说明；无需外部依赖的部分仍应保持可用。

## 八、验收、证据与恢复

本任务有6个具名验收场景，详见独立用例文档。执行观察方式：放入可搜索但不可用的秘密标记，捕获请求头和出站目标，扫描响应、日志、浏览器存储与导出内容。验收证据包含实际输入或最小fixture、动作、预期与实际结果、命令退出码、相关实体ID或版本以及失败定位。

清理与恢复：撤销测试配置、删除测试秘密、关闭恶意测试页面，并确认正式安全设置没有被测试改弱。没有执行的用例只能标为未执行或环境阻塞。使用测试替身的结果不得写成真实外部服务已经通过；模拟的成功响应也不能出现在正式产品中冒充功能。
