# T014｜保存接口与采集幂等


任务编号：**T014**。所属阶段：**G1｜离线知识库闭环**。状态：**待实现**。这是实施规格，不是已经执行的测试报告。

## 一、目标与用户可见结果

为每次保存建立清晰的事务与幂等语义，解决双击、重试和响应丢失造成的重复条目。

该任务负责的是“HTTP契约与应用服务入口”。合格实现不仅要在正常样例上工作，还必须守住这里规定的不变量。它不授权扩大MVP范围，也不授权替换整个技术栈。功能完成以后，应能通过本任务验收文件独立判断，而不是依赖实现者口头说明。

## 三、输入与输出契约

**输入：** captureRequestId、rawText、sourceType、sourceRef以及本地请求令牌。

**输出：** 新Item或同一请求的既有Item；稳定ID；明确冲突错误；已递增的数据集版本。

本任务允许：校验来源、请求体、幂等键、字段和响应格式。边界以外：不得在路由文件里复制业务模型或将未经校验的请求直接拼SQL。输入来自外部时先验证，内部状态只由该层合法操作修改。字段名、枚举、数量限制和版本行为以规范契约为准，不依据UI文案自行创造另一种类型。

## 五、必须逐条落地的规则

### T014-R01

创建接口先检查请求体字节数、schema、空文本和来源字段，再开启写事务；系统字段由服务端生成。

### T014-R02

规范请求指纹包含原文与来源字段，不包含随机生成的服务端时间；相同请求键与相同指纹返回同一结果。

### T014-R03

相同请求键不同指纹返回409，不擅自覆盖旧内容；新的用户采集动作始终使用新键。

### T014-R04

初始capturedText和rawText相同，rawVersion与revision均为1，status为raw，标题摘要允许空字符串。

### T014-R05

创建条目与datasetRevision增量同事务；响应必须在提交后返回，不能先乐观宣称保存成功。

### T014-R06

内容相同但请求键不同允许保存，最多给重复提醒；用户可能有意记录不同来源中的相同观点。

## 六、装配顺序与局部实现策略

第一步确认前置输出已经可读取，列出本任务实际要消费的字段与函数。不要先画完整界面再发现上游没有需要的版本或ID。第二步在责任层实现核心转换或操作，先用最小输入验证成功分支，再加入边界输入和错误分支。

第三步连接上下游：上游是统一客户端，下游是纯参数Service；HTTP只负责协议，不拥有独立知识副本。第四步把状态变化和错误反馈接到实际使用入口，明确何时允许用户再次操作。第五步运行本任务的正常和反例用例，复核不应发生的副作用，而不是只观察表面结果。

最后执行与本任务相关的类型检查、单元或集成测试，并在必要时跑浏览器。局部实现通过后再执行上一个Gate的冒烟回归，防止共享模块改动破坏已经可用的采集与数据路径。

## 七、状态、错误与一致性检查

重点观察：请求键、错误码、目标实体及相关datasetRevision。在测试前记录基线，在测试后比较目标变化与未授权变化。发生错误时必须遵循统一错误协议，不能把异常吞掉后返回空成功，也不能用随机重试掩盖不确定的提交状态。

关键负向要求：拒绝请求不应发生领域写入或外部模型调用；读取接口不应触发修改。错误响应必须同时检查状态码和error.code；返回200包裹失败或返回失败但已经写入都不合格。若当前任务涉及外部依赖，不可用时给出明确降级或阻塞说明；无需外部依赖的部分仍应保持可用。

## 八、验收、证据与恢复

本任务有6个具名验收场景，详见独立用例文档。执行观察方式：记录HTTP状态、响应envelope、requestId、请求次数以及调用前后数据库关键行数量和版本。验收证据包含实际输入或最小fixture、动作、预期与实际结果、命令退出码、相关实体ID或版本以及失败定位。

清理与恢复：清空本用例幂等键和临时数据库，保留脱敏请求响应以便复现。没有执行的用例只能标为未执行或环境阻塞。使用测试替身的结果不得写成真实外部服务已经通过；模拟的成功响应也不能出现在正式产品中冒充功能。

## 九、交接给下一个任务

交接时说明新增公开函数、DTO或组件的名字，列出已验证规则和仍阻塞的事项。不要把实现细节藏在临时聊天记录里。后续任务只应依赖本任务稳定输出，不应读取私有内部状态或复制SQL。改变契约必须同步其权威文件和所有受影响用例。

完成标准是：规则有实现位置，用例有执行证据，错误有可恢复路径，共享数据没有新增歧义。不能用“页面已经画出来”代替这个标准。
