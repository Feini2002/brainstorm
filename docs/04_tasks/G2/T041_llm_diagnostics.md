# T041｜模型用量、输入范围与错误诊断


任务编号：**T041**。所属阶段：**G2｜LLM整理与可靠运行**。状态：**待实现**。这是实施规格，不是已经执行的测试报告。

## 一、目标与用户可见结果

让用户知道一次整理发送了多少材料、用了哪个连接和为何失败，但不编造精确费用，也不把诊断变成秘密泄露入口。

该任务负责的是“安全诊断与事实记录”。合格实现不仅要在正常样例上工作，还必须守住这里规定的不变量。它不授权扩大MVP范围，也不授权替换整个技术栈。功能完成以后，应能通过本任务验收文件独立判断，而不是依赖实现者口头说明。

## 三、输入与输出契约

**输入：** Run安全快照、候选数量、来源ID数量、供应商返回usage、耗时和错误码。

**输出：** 可读运行详情、未知用量标记、实际尝试次数、可复制安全故障摘要。

本任务允许：记录实际运行信息、分类错误、提供限长白名单摘要。边界以外：不得根据字数编造精确token费用或将完整笔记作为默认日志。输入来自外部时先验证，内部状态只由该层合法操作修改。字段名、枚举、数量限制和版本行为以规范契约为准，不依据UI文案自行创造另一种类型。

## 五、必须逐条落地的规则

### T041-R01

显示model标识、baseUrl的安全origin、promptVersion、操作类型、开始结束时间与耗时。

### T041-R02

只显示供应商实际返回的token用量，缺失则未知；费用不根据统一价格表猜算。

### T041-R03

显示候选数量和选择来源数量，提供回到来源条目的入口，不默认展示完整外发消息。

### T041-R04

记录结构修复次数与网络请求次数，明确中止请求不保证供应商停止计费。

### T041-R05

错误分为配置、鉴权、限流、网络、截断、格式、语义验证、本地冲突与本地存储。

### T041-R06

导出诊断只用白名单，不含Key、原文、完整服务端路径和安全令牌。

## 六、装配顺序与局部实现策略

第一步确认前置输出已经可读取，列出本任务实际要消费的字段与函数。不要先画完整界面再发现上游没有需要的版本或ID。第二步在责任层实现核心转换或操作，先用最小输入验证成功分支，再加入边界输入和错误分支。

第三步连接上下游：各层报告统一requestId和runId，但不把整条请求内容贯穿日志；用户据错误层级选择排查路径。第四步把状态变化和错误反馈接到实际使用入口，明确何时允许用户再次操作。第五步运行本任务的正常和反例用例，复核不应发生的副作用，而不是只观察表面结果。

最后执行与本任务相关的类型检查、单元或集成测试，并在必要时跑浏览器。局部实现通过后再执行上一个Gate的冒烟回归，防止共享模块改动破坏已经可用的采集与数据路径。

## 七、状态、错误与一致性检查

重点观察：日志字段、计数、错误分类、运行用量与诊断文件。在测试前记录基线，在测试后比较目标变化与未授权变化。发生错误时必须遵循统一错误协议，不能把异常吞掉后返回空成功，也不能用随机重试掩盖不确定的提交状态。

关键负向要求：诊断读取不改变知识和Run，不引入第三方遥测，也不通过分享摘要扩散私人内容。观测不到的数据应写未知或未执行，不允许填入看似合理的默认数值。若当前任务涉及外部依赖，不可用时给出明确降级或阻塞说明；无需外部依赖的部分仍应保持可用。

## 八、验收、证据与恢复

本任务有6个具名验收场景，详见独立用例文档。执行观察方式：核对日志事件、响应摘要、用量来源和关联ID，同时扫描所有产物中的秘密与原文标记。验收证据包含实际输入或最小fixture、动作、预期与实际结果、命令退出码、相关实体ID或版本以及失败定位。

清理与恢复：清理测试日志并检查轮转限制，保持正式日志策略和受保护接口不变。没有执行的用例只能标为未执行或环境阻塞。使用测试替身的结果不得写成真实外部服务已经通过；模拟的成功响应也不能出现在正式产品中冒充功能。
