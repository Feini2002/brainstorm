# 无Embedding候选召回：精确算法、预算与已知盲区


## 1. 为什么不是只取最近四十条

最近列表可以让刚输入的相关片段相遇，却会逐渐遗忘旧材料。MVP 不接向量模型，仍能增加低成本的字面检索通道。它解决“同词的旧知识能不能找回”，不解决所有同义关系；界面不能称其为全库语义搜索。Graph里没有连线不代表两条材料毫无关系。

定义 CandidateSelector v1：输入目标 Item、最多四十条预算；输出有序 CandidateBrief[] 与 retrievalVersion='lexical-v1'。每条记录 id、title、summary、tags、evidenceSnippets、retrievalReason。retrievalReason 仅用于诊断，不是模型关联评分。搜索不调用任何外部API。

## 2. 查询词生成

取目标 title、keywords、tags 和 rawText 的前两千码点。标签与关键词每项规范化为NFKC、小写、空白折叠；原始资料不改。英文/数字连续串长度二到四十视为词，最多十六个。中文连续段生成长度为二的相邻片段，去掉预定义停用片段，例如“的是”“一个”“我们”，按首次出现次序最多十六个。完整标签短语优先，再选词和二元片段，总共最多二十四个查询项。

停用列表写在代码常量并版本化，不能由模型每次自由改变。目标只有一个字或无有效词时，不生成假词；走最近候选回退。中文片段会产生噪声，因此只能作为弱特征，不单凭一个常见二元片段认定关系。

## 3. 有界取样和排名

最近通道读取除自己外最近十二条。字面通道在标题、摘要、raw_text 和标签规范值中执行参数化 LIKE；每个查询项最多取五十条，合并后总候选池最多二百条。SQL中的 `%`、`_` 与转义字符都按字面处理。池上限达到时稳定保留得分较高且更新较新的条目，不循环扫描全库所有内容再丢给浏览器。

分数是工程排序：完整标签重叠每项加八分，上限二十四；完整关键词在标题命中每项加四分，上限二十；完整词在摘要命中每项加二分，上限十二；中文二元片段命中每项加一分，上限六；rawText命中每项加一分，上限六。完全无命中不进入字面通道。时间只用于同分排序，优先 updatedAt 较新、再按 id。

先保留最近通道的十二条，再从字面排名补足到四十条。去重键是 Item.id，排除目标自身。若最近不足十二条，剩余名额仍供字面通道；若总量不足四十，不制造占位条目。结果中同一Item只出现一次，不把某标签重复算作多个候选。

这是一种可解释而非最优的检索设计。正式实现须用包含一百条无关新记录和一条相关旧记录的fixture验证旧知识能进入；用“不同用词但实际近义”的fixture记录局限，不把失败偷偷改为假成功。以后加入Embedding时保留接口，替换候选生成，不改关系应用契约。

## 4. 证据片段与隐私预算

模型不能引用没看过的原文。每条 CandidateBrief 的总文本预算二百四十码点，由 title≤五十、summary≤七十、tags合计≤三十、evidenceSnippets合计≤九十组成，剩余用于安全分隔。片段来自原始rawText的逐字连续子串，优先包含命中词周围，不把摘要伪装成原文引用。最多两段，各自保留 startOffset 可供服务端追踪，但模型只需返回逐字quote和itemId。

中文或emoji截断按码点，不能截出半个代理对。候选没有匹配片段时可以选择原文前段，但不得自行“提炼”一段当证据。目标原文完整提供，候选只提供受限片段；模型需要关系证据时只能从实际提供的这些字符串摘录。

出站打包总计不超过二万四千码点，包含系统约束、目标、候选、schema描述与用户意图。这里不是token精确计量，界面展示“预计发送若干条材料、约若干字”，不用固定除以四制造准确token账单。用户必须能在操作前看到发送范围，至少知道会包含本次候选旧笔记。

## 5. 搜索与关联是不同能力

Library搜索用于找已存在文本，立即显示；CandidateSelector用于给整理模型缩小比较范围；RelationClassifier由LLM判断受限候选间关联。三者不能混成“搜索结果就是关系”。用户点搜索不能触发模型费用，切换标签也不能隐式重建图谱。

本版不进行全库自动重连。旧知识只有作为候选被比较或用户主动重新整理时才可能新增关系。上线说明要写出这个触发规则，避免用户以为每天打开软件就会自动把整个库重新推理一遍。以后批处理要有预算预览、取消、幂等与恢复规格，不能仅写一个 for循环。
