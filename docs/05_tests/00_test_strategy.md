# 测试总策略、证据分级与最终验收标准


## 1. 四种通过不能混为一谈

规格包审计通过：Markdown链接、JSON格式、任务依赖、参考SQL约束和参考schema样例一致。本交付可以验证这一层。单元/集成测试通过：应用实现的函数与API在替身和隔离数据库上工作。浏览器验收通过：真实页面、操作、生命周期和刷新持久化工作。真实模型验收通过：用户自己的端点、模型和Key实际调用并由人检查语义质量。

前一层不能替代后一层。不能用一张ReactFlow demo截图证明本地数据库恢复，不能用一个固定JSON模拟响应证明服务商支持结构化模式。最终报告分别列出passed、failed、blocked、not_run，并说明证据范围。

## 2. 单元测试范围

纯函数包括标签规范化、码点和字节限制、cursor解析、canonicalJson/hash、关系端点规范化、Item状态推导、候选分数与片段、图源AST校验、Markdown与Mermaid编译、来源快照比较、字段锁合并和错误码映射。输入集合至少包含空、边界、重复、特殊字符、越界、错误类型与恶意字符串。

不把Date.now、Math.random和全局fetch写死在难以测试的位置。时钟、UUID生成和transport通过小型接口注入；生产默认用真实实现，测试用确定实现。不要为了测试引入完整依赖注入框架。

## 3. 数据库与API集成

每个测试组创建临时目录与独立SQLite，启用和生产相同的PRAGMA与迁移。测试结束关闭连接再删目录，Windows文件锁错误不能通过忽略清理掩盖。测试运行前检查目标目录不等于用户.data；代码里明确禁止对用户目录执行reset。

至少验证采集幂等、同键异内容、乐观编辑冲突、不可变capturedText、标签去重、关系对称规范、拒绝墓碑、全局Run唯一、模型期间编辑冲突、迟到响应、恢复原子性、级联删除、导出白名单和导入回滚。用另一个连接或受控事务模拟竞争，而不只顺序调用两个函数后宣称并发已验证。

HTTP测试必须经过限长、Origin/Token、schema、Service和Repository。transport替身只能替换外部HTTP，不能让路由直接返回已整理Item。统计请求次数，确认超时和429没有隐藏重试；格式修复开启时第二次请求被明确记录。

## 4. 浏览器测试

Playwright使用Chromium与独立APP_ORIGIN。至少执行无Key采集→刷新→编辑→查询、设置保存/测试、AI成功/失败双阶段提示、关系审核、Graph布局保存、Mindmap/Flow来源回跳、过期视图、导出恢复和键盘访问。每一步有DOM断言和必要API/数据库断言，不只截图。

专门测试React Strict Mode重复挂载、来回切图十次、ResizeObserver清理、旧Mermaid异步结果晚返回、标签很长导致高度变化、空库和零关系。图可视化测试截图可以辅助，但坐标像素完全一致不应成为跨平台唯一断言。

恶意标签包括script片段、onerror属性、javascript链接、Mermaid click/init、Markmap远端资源标记、Unicode控制字符。验证没有脚本执行、没有未知网络请求、没有未经净化的DOM入口；不只检查字符串里有没有某个单词。

## 5. 性能目标是测量目标

目标数据集建议一千条知识、三千关系、二十保存视图，另测Graph上限200/600与输出边界。记录CPU、内存、Node版本和开发/生产模式。采集、查询、图初显、布局与渲染分别测量；不要把远端模型延迟算成本地CRUD缺陷，也不能拿开发HMR开销当正式生产数字。

建议在目标机器上以生产模式验证保存与简单查询p95不超过300毫秒、图上限下交互不出现持续数秒主线程冻结；这是待测工程预算，不是本方案已经实现的承诺。未达标先检查重复请求、全量读取、大库静态导入和无界渲染，不立即引入Redis或微服务。

## 6. 语义验收

使用彼此相关、无关、互相矛盾、转述未赞同、含条件限制、极短词语和指令注入材料。检查标题摘要是否忠实、是否保留不确定性、标签是否重复膨胀、关系是否牵强、因果是否被乱加、图来源是否完整。允许零关系和小图；不能要求每条笔记都产生“丰富”结果。

记录使用的provider/model/profile、提示词版本、材料数量、实际失败类别和人工观察，不公开Key。真实模型质量随端点和模型改变，结构校验并不保证每次都语义正确；用户审核与原文追溯仍是产品能力。

## 7. 完成证据

每个任务有六个具名场景，共504个规格场景。它们不是预先通过的504项测试；实施时可把多个场景映射到一个参数化测试，但记录对应ID。最终任务manifest状态从not_started→in_progress→blocked/verified变化，不允许仅因文件存在就verified。

Gate结束报告包含执行命令、退出码、测试数量、失败/阻塞、未执行项、关键截图路径、数据完整性检查和新增依赖。真实服务不可用可标blocked，但不能在此情况下宣称完整MVP外部AI验收已经完成。
