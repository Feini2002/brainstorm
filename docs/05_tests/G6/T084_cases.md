# T084 验收用例｜最终用户旅程与MVP完成定义


本文件是**测试规格**，不是测试结果。实施入口：[T084 最终用户旅程与MVP完成定义](../../04_tasks/G6/T084_final_acceptance.md)。所属 Gate：G6。规范字段和限制见 [契约索引](../../03_contracts/00_contract_index.md)。

## 公共测试装置

用例使用隔离数据与不可用的测试秘密。任何真实连接验证都应单独记录，并由用户在自己的设置页配置。自动化测试不得连接默认用户数据库。外部依赖替身不得绕过业务校验和事务。

观察方法：保存命令、退出码、测试ID、最小输入和预期实际差异，必要时附安全截图及数据库观察。

基线与状态：用例结果、Gate状态、临时数据、报告与明确未执行项。

整个用例组不可违反：测试不触碰用户数据库和可用Key，不自动修改架构来迎合断言。

清理方法：关闭测试服务和浏览器、清理独立目录，保留脱敏失败样本与可重复执行命令。每个场景必须从明确基线开始，不依赖上一场景残留的缓存或运行记录。幂等测试要明确有意复用的键，非幂等测试不得误复用。

实际执行结果应追加到 implementation/progress/evidence/ 下，不直接把规格的预期句改成已完成结论。浏览器截图、数据库断言、外部请求次数分别证明不同事情，不能相互替代。

## T084-C01｜新仓库启动

**前置：** 只有方案指导与实现提交。

**动作：** 按README从零运行。

**必须断言：** 能进入Inbox且基础记录真实可用。

**必须排除：** 交付应能在干净环境复现。



## T084-C02｜Key前端配置

**前置：** 没有手工编辑env。

**动作：** 在Settings配置连接。

**必须断言：** 测试与整理可用，Key不回显。

**必须排除：** 用户明确要求系统内设置入口。



## T084-C03｜多视图同源

**前置：** 同一批Item用于三个图。

**动作：** 分别检查来源。

**必须断言：** 共享真实ID，无独立知识副本。

**必须排除：** 这是系统整合的核心价值。



## T084-C04｜人工控制

**前置：** 修改摘要并拒绝一条边。

**动作：** 再次整理。

**必须断言：** 手工修改和拒绝决定保持。

**必须排除：** 自动化必须尊重纠正。



## T084-C05｜恢复证明

**前置：** 导出并恢复到空库。

**动作：** 打开原文和保存视图。

**必须断言：** 数据与来源关系等价，Key需独立配置。

**必须排除：** 备份价值由恢复验证。



## T084-C06｜完成边界

**前置：** 所有硬条件通过。

**动作：** 发布最终说明。

**必须断言：** 范围准确，不承诺未做能力。

**必须排除：** MVP完成不等于未来所有功能都具备。
