# T003 验收用例｜工程目录与服务端隔离


本文件是**测试规格**，不是测试结果。实施入口：[T003 工程目录与服务端隔离](../../04_tasks/G0/T003_repo_boundaries.md)。所属 Gate：G0。规范字段和限制见 [契约索引](../../03_contracts/00_contract_index.md)。

## 公共测试装置

用例使用隔离数据与不可用的测试秘密。任何真实连接验证都应单独记录，并由用户在自己的设置页配置。自动化测试不得连接默认用户数据库。外部依赖替身不得绕过业务校验和事务。

观察方法：记录执行命令、退出码、实际解释器路径与生成文件列表；对文件操作比较目录前后快照。

基线与状态：项目脚本、配置和临时探针文件。

整个用例组不可违反：没有新增模型调用，没有修改真实.data，未改变全局registry或证书配置。

清理方法：关闭本用例启动的进程，只删除本用例临时文件，保留原锁文件用于复核。每个场景必须从明确基线开始，不依赖上一场景残留的缓存或运行记录。幂等测试要明确有意复用的键，非幂等测试不得误复用。

实际执行结果应追加到 implementation/progress/evidence/ 下，不直接把规格的预期句改成已完成结论。浏览器截图、数据库断言、外部请求次数分别证明不同事情，不能相互替代。

## T003-C01｜错误客户端导入

**前置：** 一个 use client 文件直接导入数据库模块。

**动作：** 执行构建与边界检查。

**必须断言：** 构建或静态检查明确失败，不能靠移除 server-only 通过。

**必须排除：** 秘密与文件操作可能进入浏览器打包路径。



## T003-C02｜公共类型复用

**前置：** 页面和 API 都需要 ItemDTO。

**动作：** 从 domain 导入纯类型。

**必须断言：** 两侧能编译且类型模块没有运行时文件副作用。

**必须排除：** 用服务层类型强行复用导致前后端耦合。



## T003-C03｜路由变薄

**前置：** 新增一个读取条目接口。

**动作：** 审查 route 文件和 service 测试。

**必须断言：** route 只做保护、解析、调用、映射错误。

**必须排除：** 业务散落路由导致难以覆盖分支。



## T003-C04｜构建阶段

**前置：** 数据库目录不存在。

**动作：** 执行纯类型检查与生产 build。

**必须断言：** 没有创建真实 brain.db。

**必须排除：** 模块导入副作用造成构建污染用户数据。



## T003-C05｜测试替换

**前置：** 服务依赖模型 transport。

**动作：** 给服务注入测试 transport。

**必须断言：** 不用改页面或数据库模块即可测试。

**必须排除：** 难以替换外部服务会逼迫测试使用真实 Key。



## T003-C06｜目录漂移

**前置：** 第二个任务新建一个重复 schemas 目录。

**动作：** 执行架构审查。

**必须断言：** 要求复用 domain schema 并删除重复权威定义。

**必须排除：** 多个类型来源会在后续修改中产生不兼容。
