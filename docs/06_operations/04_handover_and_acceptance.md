# 交接包、验收证据和后续修改规则


## 1. 应用实施交接必须包含什么

完成后的仓库应包含实际应用代码、锁文件、版本化SQL迁移、单元/集成/浏览器测试、可执行README、依赖冻结报告、环境doctor、备份恢复说明和任务进度。当前规格包提供的是这些产物的要求，不冒充它们已经存在。

README要能让未参与开发的人知道Node范围、npm ci、构建与启动命令、地址、数据目录、设置Key方法、没有Key可用功能、停止服务方式、备份恢复和已知限制。不能只写“npm run dev即可”却没写当前仓库尚无代码。

## 2. Gate0到Gate6顺序

G0验证本地运行、请求安全和数据库；G1验证离线笔记；G2验证模型与运行可靠性；G3验证关系图；G4验证脑图；G5验证流程；G6验证恢复、安全、生产构建和整体体验。前置能力尚未可用时，不用假API或全局mock把后面页面先画成完成状态。

每个Gate完成后保存一次可运行的Git提交，提交信息包含Gate与任务范围。文档任务状态不是Git历史替代；代码变更不依赖只存在于聊天中的临时决定。跨Gate共享缺陷修复要加回归并更新受影响契约，不静默改掉既有接口。

## 3. 最终人工旅程

先无Key保存一个词、一句话和多段文字，刷新后读取；编辑一条原文确认初始capturedText仍可查看；在Settings测试并保存配置；整理几条材料，确认原文先保存、人工摘要不被覆盖、关系可以接受和拒绝；打开Graph，拖位置保存并刷新；选择材料生成Mindmap和Flow，点击来源回到同一Item；改其中原文确认旧视图显示过期；导出并在空临时库恢复；删除Key确认全部非AI能力还可用。

最后运行lint、typecheck、unit、integration、e2e和production build，在start模式重复最小旅程。记录实际命令与结果。端口关闭后重启再读取，确保不是仅内存状态。查看日志和导出确保测试秘密标记不出现。

## 4. 允许延后与不允许延后

允许延后自由白板、Markdown富编辑、Embedding、云同步、移动端安装包、浏览器剪藏插件、批量Agent整理、SVG/PNG/PDF导出和高级布局。它们不阻断此MVP。

不能延后原文持久化、Key不回显、输入与输出校验、错误和中断状态、用户编辑保护、来源追溯、版本冲突、逻辑导出及恢复路径。把这些称“以后再补的工程细节”会使产品看似能演示却不适合存放真实资料。

## 5. 变更请求模板

每次变更写：当前问题、可观察证据、提议方案、被替换职责、数据格式影响、迁移策略、依赖/许可影响、风险、验收和回滚。小样式修复不必写长ADR，但新增数据库、Provider、后台worker或另一套笔记身份必须经过该模板。

后续优化先以真实数据判断，优先修复慢、错、丢、不可恢复四类问题，再扩展漂亮视图。没有用户资料和操作记录时不要凭想象重构成企业知识中台。保持“单一知识数据，多种受控视图”这一主干。
