## 一、结论

G3 把「领域子图 → React Flow 画布 → Dagre 布局 → 视图持久化」做成了一个闭环，而不是三个
各自能跑通的演示页面。这一阶段真正需要证明的四件事：

- **源头只有一个。** 图上的节点与边来自 `/api/graph` 读取的真实条目与关系，页面不接受硬编码
  数组，验收用例按 id 比对图读与资料库读的结果（`T052-C01`）。
- **展示不写知识。** 拖动、自动布局、保存布局只写 View 的 `content_json` 与 `revision`；
  条目版本、原文版本、关系审核状态都不动（`T051-C03`、`T052-C03`）。
- **过期是派生的，不是存的。** 库里没有 `is_stale` 列，边的 `freshness` 在每次读取时由
  `rawVersion` 比较得出（`T051-R06`）；图读与关系读共用同一次派生，所以两处不可能各自漂移
  （`T051-C06`）。
- **大图有明确降级。** 超过画布预算时区分「当前图」「筛选共匹配」「知识库合计」三个数字，并
  保留列表与检索入口，不假装整库都画出来了（`T050-R01`、`T052-C04b`）。60 节点实测：
  打开 530ms、自动布局 105ms、拖动 536ms（本机 Chromium，见证据第 4 节）。

## 四、规则落点（逐条）

- **T043-R03** 展示预算（`graphNodes` 200 / `graphEdges` 600）由领域函数持有，读取窗口
  （`READ_FLOOR = 500`）在其之上，所以 `matched` 与 `shown` 是两个不同的数字，截断提示才会真的
  触发。读取恰好等于预算的一批数据时 `truncated` 为 false（`T052-C04b`）。
- **T043-R06 / T044-R05** `hasSavedPosition` 由正在渲染的 View 派生，读取路径从不发明坐标。
- **T045-R02** `nodeTypes` / `edgeTypes` 是模块级常量；每次渲染新建对象身份会让 React Flow
  重挂载所有节点，拖动的中点会丢焦点。
- **T046-R01** 自动布局是按钮，不是 effect：没有任何渲染会调用 Dagre，所以切换筛选或改标题
  不会悄悄重排用户摆好的位置。
- **T046-R05** 布局结果非法时拒绝写入并提示，保留原坐标。
- **T047-R01** 布局写入只包含 `positions` / `direction` / `viewport`，落在 `views.content_json`。
- **T047-R02** 拖动按帧产生 change，但只提交 `dragging === false` 的那一次，十个节点拖动不会产生
  上百次 SQLite 写入。
- **T047-R03** 409 时保留本地草稿并停止自动保存；不会覆盖另一窗口，也不会丢弃用户刚摆的位置。
- **T047-R06** 基线未就绪时的拖动被忽略，避免把空 draft 覆盖到已存坐标上。
- **T048** 阈值只隐藏边、不删除行；人工边（`score === null`）不受评分阈值约束；连续改筛选
  只有最后一次查询的结果被采用。
- **T049-R02** 边的 `evidence` 随图读一起返回，检查面板显示引文与版本，理由不铺在画布上。
- **T049-R03** 审核一个边只刷新受影响的边，不整页重载；旧 revision 审核返回冲突，不用乐观 UI 掩盖。
- **T050-R01/R02** 三个计数分开显示；不用画布也能通过关系列表与检查面板读到同样的关系与来源。
- **T050-R04** 建议/已确认/过期同时用线型与文字表达，不只靠颜色。
- **T051-R01** 节点携带 `rawVersion`，边携带 `sourceRawVersion` / `targetRawVersion`，客户端不需要
  第二次请求就能判断过期。
- **T051-R02** 原文变化只标记「依据过期」，不改关系的 `reviewStatus`。
- **T051-R06** 新鲜度是读取时派生；`knowledge_items` / `relations` 上没有 stale 布尔列。
- **T052-R05** 组件边界由源码扫描证明：`src/features/graph/**` 与 `graph/page.tsx` 不含
  `node:sqlite`、`DatabaseSync`、内联 SQL、`server-only`、`@/server/`、秘密模块，也不引用
  `BRAIN_DATA_DIR`。

## 五、本轮 review 发现并修复的真实缺陷

G3 收尾做了一轮 review，下面每一条都有可复现的失败现象，不是风格偏好。

| 缺陷 | 后果 | 修复 |
| --- | --- | --- |
| `getGraphData` 在**全库关系**上派生新鲜度 | 端点不在本次读取范围内的关系被判为 `missing`，UI 显示「端点已删除」——而那条记录只是没被读进来。用户会以为自己的数据被删了 | 改为只在 `coveredRelations`（两端版本都在本次读取窗口内）上派生；`staleCount` / `missingCount` 现在只反映**当前图范围** |
| `GraphEdge` 缺少 `evidence` 字段 | 检查面板要求用户接受或拒绝模型判断，却看不到判断依据的那段原文；这正是「引文」与「装饰」的区别（T049-R02/C02） | 领域 DTO 增加 `evidence: Evidence[]`，由 `buildGraph` 从关系行投影（引文在写入时已逐字校验过，不是新断言），检查面板逐条显示并标注出处 |
| E2E 拖动用例把节点拖到**视口外** | `boundingBox()` 对折叠线以下的节点照样返回坐标，但瞄准 `y > innerHeight` 的鼠标事件谁也收不到，拖动静默失效；断言用 `boundingBox` 差值还可能因画布平移产生假通过 | 新增 `dragNode()` 辅助：先把节点滚进视口、断言它完整落在视口内，再按下/移动/松开并比较 `transform`；`T049-C03`、`T051-C03` 都改用它 |
| 用 `boundingBox()` 断言节点尺寸 | 该值在**屏幕空间**，会被 React Flow 的 `fitView` 缩放：208px 的卡片在 zoom 1.04 下读成 216px，看起来像「节点被长标题撑大了」 | 新增 `nodeLayoutSize()` 读 `offsetWidth/offsetHeight`（变换前的布局尺寸，也就是告诉 Dagre 的那个数），断言严格等于 `NODE_WIDTH`/`NODE_HEIGHT` |
| `T052-C03` 用 `save` 按钮等待布局落库 | 拖动已被防抖自动提交，按钮早已变成 disabled 的「布局已保存」，点击超时；而在拖动前后各读一次视图又会与防抖计时器竞态 | 改为在拖动**之前**读一次存储行，拖动后轮询到 `revision` 前进且坐标变化，证明写入真的发生 |
