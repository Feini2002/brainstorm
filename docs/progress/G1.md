## 一、结论

在没有任何 LLM 配置、且全部外部域名不可达的条件下，本应用已经是一款可用的本地碎片笔记：
可以创建、检索、编辑、建立人工关系、删除，并能在**进程重启**后读回同一份数据。
智能整理未在本阶段声称可用；需要模型的操作会明确说明缺少配置，而不是给一个空画布。

## 四、规则落点（逐条）

- **T013-R03** IME：`CaptureBox.onSubmitShortcut` 检查 `nativeEvent.isComposing || keyCode === 229`，Enter 只换行。
- **T013-R05 / T025-R05** 只在提交快照未被改动时清空草稿：比较 `draftRevision` 与提交时的快照文本。
- **T014-R02/R03** 幂等：`capture_request_id` 唯一约束；首次 201，重放 200 且指向同一 ID。
- **T019-R04** CAS：`expectedRevision` 不符返回 409 `REVISION_CONFLICT`，不覆盖另一写入方。
- **T021-R01** 选择只存 ID；生成前由服务端重读条目与版本。
- **T021-R04** 删除的已选条目立即从选择移除并计入 `removedIds`，托盘显示数量（见第五节缺陷）。
- **T022-R03/R04** 人工关系 `score = null`；同规范键的 AI 建议就地升级为人工，不插平行边。
- **T023-R01/R02** 三种状态都留在库中；`rejected` 不进默认查询但保留去重键（拒绝不复活）。
- **T024-R01** 无 `next/font/google`、无 CDN 资源；字体栈为系统 UI 字体 + 中文字体。
- **T025-R01/R02** `MutationStatus` 区分 `saving / saved / unknown / failed`；整理失败不改写「已保存」。
- **T025-R03** 草稿只在模块级内存 store，不写 localStorage；未提交内容注册 `beforeunload`。
- **T026-R03** 持久化证据是**进程重启**（pid 与 token 都变化），刷新浏览器不被采信。

## 五、本轮 review 修复的实际缺陷

| 缺陷 | 后果 | 修复 |
| --- | --- | --- |
| `listItems` 把游标条件拼成 `FROM t AND (...)` | 无筛选时第 2 页 SQL 语法错误 | 游标条件并入同一个 `WHERE` 构造器 |
| `SORT_SQL` 未限定表名 | join 后 `ORDER BY` 二义 | 限定为 `knowledge_items.*` |
| `ITEM_COLUMNS` 未限定表名 | `ambiguous column name: id` | 全部限定表名 |
| 列表查询未选 `capture_request_id` | 列表路径解码缺字段（潜伏） | 一并修复并加回归用例 |
| `decodeEvidence` 按 `item_id` 读取 | 与约定 `itemId` 不符，读到 `undefined` | 接受 `itemId`，兼容旧写法 |
| Turbopack 动态文件系统访问警告 | 构建噪声掩盖真实警告 | `turbopackIgnore` 标注 + `outputFileTracingExcludes` |
| 删除只由资料库 effect 清理选择 | 在收件箱删除会留下陈旧选择 | 新增 `dropDeleted`，删除时立即清理 |
| 无模型时的「缺少配置」提示被成功回调清掉 | 用户看不到失败原因 | 提示存入草稿 store，由下次输入或提交清除 |
| Ctrl+Enter 绕过按钮的保存中禁用 | 一次思考可能产生两条记录 | `submit` 内统一拦截重复提交 |
| textarea 在保存中被禁用 | 「旧响应清空新草稿」的竞态无法成立 | 保持可编辑，只禁用按钮 |
| 契约守卫用 `.includes('.data')` 判断忽略项 | 真实数据目录可被提交而检查仍绿 | 改为整条目录项匹配 + 2 个回归用例 |
