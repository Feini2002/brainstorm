## 三、G0 期间的实际缺陷与修复

### 3.1 2026-09-15 补测修复（T003 / T006）

| 缺陷 | 后果 | 修复 | 回归 |
| --- | --- | --- | --- |
| `eslint.config.mjs` 的 `feini/domain-purity` 规则 `files: ["src/domain/**/*.ts"]` | ESLint 的 `*.ts` **不匹配** `.tsx`：一个放进 `src/domain/` 的 React 组件绕过全部五条 domain 纯净规则，可以在「纯类型、schema 与无副作用函数」层里 import React 或 `@/server`，T003-R01 事实上漏掉这类文件 | 改为 `files: ["src/domain/**/*.{ts,tsx}"]` | `tests/contracts/architecture.test.ts` T003-C02/R01（虚拟文件名 `src/domain/architectureProbe.tsx`）；把 `"react"` 从规则 group 里删掉即失败 |
| `apiClient.parseEnvelope` 只有 `body.ok === true` 一个判断，随后直接 `throw new ApiClientError(body.error, ...)` | 对端返回合法 JSON 但不是本项目信封时（占位网关的 `{"data":[]}`、门户的 `{"error":"…"}`），`body.error` 为 `undefined`，构造函数读 `error.code` 抛 `TypeError: Cannot read properties of undefined`。统一信封的意义是「失败也有稳定形状」，这条路径下用户拿到裸异常，`requestId` 也丢了 | 增加 `isSafeError` 形状判定与 `failureFromBody` 回退，非本项目信封统一映射为「本地服务返回了无法识别的响应（HTTP xxx）」并保留 `x-request-id` | `tests/unit/api-envelope.test.ts` T006-C06 两组（`ok` 缺失、`ok:false` 但 `error` 是字符串）；把 `isSafeError(candidate.error)` 改回 `if (candidate.error)` 即失败 |
