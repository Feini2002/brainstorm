# DOMPurify：优势、复用颗粒度与装配边界


## 采用结论

已选：HTML 与 SVG 边界的净化器。本文将上游公开能力与本项目设计分开；来源索引：S16，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

React 默认文本转义覆盖不了第三方库插入的 HTML 或 SVG。Markmap 标签与 Mermaid 输出存在这样的边界，因此引入专门的净化组件比写几个字符串替换更稳妥。

## 组件怎么接入

封装 sanitizeMarkmapContent 与 sanitizeMermaidSvg 两个函数，各自采用最小允许元素及属性集合。浏览器端使用 DOM 环境，不为了服务端净化额外拉入一套 DOM 仿真运行时。

## 不能让车轮子替我们决定的内容

净化只能降低可执行标记风险，不能判断用户内容是否误导，也不能自动验证来源。净化后再拼入未处理字符串会重新引入风险；净化结果只能直接进入指定渲染容器。

## 输入、输出和所有权

输入不可信标记字符串，输出受限字符串。普通笔记原文直接作为 React 文本，不经 dangerouslySetInnerHTML，也不需要为了统一而先转换成 HTML。

## 最小集成实验

使用注入样本验证脚本、事件属性、外部资源、javascript URL 和 foreignObject 等行为。Mermaid 的显示所需属性要通过实际浏览器回归，不以放开全部属性解决样式丢失。

## 替代品与不选原因

CSP 是补充，不是净化替代；strict Mermaid 配置也是补充。这里采用数据 AST、受控编译、库安全配置、净化四层边界。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
