# React Flow：优势、复用颗粒度与装配边界


## 采用结论

已选：知识关系的交互呈现。本文将上游公开能力与本项目设计分开；来源索引：S08 S09 S10，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

React Flow 的优势是节点本身可以由 React 组件组成。知识卡片、选中态、标签、详情按钮与关系审核可以使用同一套 UI，而缩放、拖动、平移、选择与控制条直接复用现成能力。

## 组件怎么接入

GraphAdapter 把 ItemDTO 变为 node，把 RelationDTO 变为 edge。nodeTypes 与 edgeTypes 定义在稳定模块位置；容器有明确高度；节点采用固定尺寸或经过测量再布局。全图状态不直接复用数据库对象引用。

## 不能让车轮子替我们决定的内容

React Flow 不会理解哪些笔记相关，也不会自动给出合适布局。它擅长交互节点，但大量 DOM 节点的开销不同于 WebGL 图网络。第一版限制显示范围，而不是假设几万条知识可以无条件全部展开。

## 输入、输出和所有权

输入 nodes、edges、positions、selection；输出节点移动、选中与用户动作。删除键默认不删除知识实体，图形交互必须经过产品层确认后才调用真正删除接口。

## 最小集成实验

测试空图、孤点、双向边、长中文标题、窗口缩放、侧栏展开、筛选后失选、位置恢复和二百节点场景。验证节点拖动不会改变 rawText、rawVersion 或摘要。

## 替代品与不选原因

Sigma 更适合后续大规模网络浏览，Excalidraw 更适合自由手绘。MVP 最需要的是可点开来源的结构化知识卡片，因此选 React Flow。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
