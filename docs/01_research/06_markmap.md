# Markmap Lib + View：优势、复用颗粒度与装配边界


## 采用结论

已选：可折叠层级视图。本文将上游公开能力与本项目设计分开；来源索引：S12 S13 S14，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

Markmap 把文本层级直接变为可缩放、可展开折叠的脑图。lib 与 view 的职责划分有利于把“生成层级”和“显示层级”分开，使不同模型输出都先进入本系统的受限树结构。

## 组件怎么接入

服务端验证 MindmapDocument，再编译为纯标题和列表 Markdown。客户端实例化 Transformer，取得 root 后净化文本内容，再交给 Markmap.create。所有图实例、观察器和事件监听在卸载时释放。

## 不能让车轮子替我们决定的内容

脑图是树，真实知识关系可能是网。不能把一条观点在多个分支出现误认为数据库有多个副本，也不能让模型为了整齐而补出没有来源的新结论。来源 ID 应随树节点保留在本系统结构里。

## 输入、输出和所有权

输入经验证的层级与来源映射；输出 SVG 与折叠交互。第一版来源跳转通过旁侧大纲按钮完成，不依赖模型生成可点击 HTML 链接。

## 最小集成实验

测试单节点、一百二十节点、深度边界、重复 ID、孤立子树、非法父节点、标签中的尖括号、代码反引号与换行。禁用任何远端资源自动加载，离线仍可浏览已保存脑图。

## 替代品与不选原因

手工用 React Flow 画树也能实现，但要自行补折叠、层级排版和大纲映射。Markmap 的直接价值是缩短这一部分交付路径，而不是取代知识数据模型。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
