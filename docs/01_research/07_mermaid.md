# Mermaid：优势、复用颗粒度与装配边界


## 采用结论

已选：受限流程投影。本文将上游公开能力与本项目设计分开；来源索引：S15，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

Mermaid 让流程结构具有可复制、可导出的文本表示。对解释步骤、依赖与假设路径，声明式图比自由拖线更容易由程序生成和校验。

## 组件怎么接入

模型只输出 FlowDocument JSON，服务端使用受控模板编译 flowchart。临时节点 ID 重新映射为安全 ID；标签转义；禁止模型输出指令、配置和 HTML。浏览器 strict 模式渲染，并对 SVG 做独立净化。

## 不能让车轮子替我们决定的内容

能够画一条箭头并不表示存在因果证据。流程边要区分 sequence、dependency、association、causal、hypothesis；缺少来源支持的推理必须标注假设，不能自动写回领域关系。

## 输入、输出和所有权

输入受限节点、边、方向与来源 ID；输出可视 SVG 和可复制语法。第一版只支持 flowchart，不引入甘特、时序、类图或全部 Mermaid 语言面。

## 最小集成实验

测试标签中的引号、分号、括号、HTML、初始化指令、恶意链接、超长图和异步响应乱序。一个渲染失败不能导致整个 Library 不可用，必须保留安全来源列表和错误提示。

## 替代品与不选原因

React Flow 更适合可拖拽编辑，Mermaid 更适合表达和导出。两者共享输入知识但不共享内部图对象，也不需要互相转换全部画布状态。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
