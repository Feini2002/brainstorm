# Dagre：优势、复用颗粒度与装配边界


## 采用结论

已选：一次性层次布局。本文将上游公开能力与本项目设计分开；来源索引：S09 S11，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

Dagre 把有向边和节点尺寸转成可读的层次坐标，减少手写排版算法的工作。它是数学布局器，不占有知识数据，也不要求改变关系的业务方向。

## 组件怎么接入

布局函数是纯适配器：复制节点和边，构造 dagre graph，设置 rankdir、nodesep、ranksep，计算后将中心坐标减去节点宽高的一半。返回新的 positions，不就地修改 React state。

## 不能让车轮子替我们决定的内容

知识图里可能有环、对称边和多个孤立分量。层次图只是帮助阅读，不意味着存在真实上下级；用户应该可以选择横向或纵向布局，手动移动后不被每次渲染重新覆盖。

## 输入、输出和所有权

输入节点 ID、尺寸、边列表和布局方向；输出 ID 到坐标的映射。传入不存在端点的边前就应过滤，否则布局问题会掩盖数据引用错误。

## 最小集成实验

用固定样本断言坐标为有限数、节点数量不变、ID 不变、输入未被修改。不要写跨版本精确像素快照；应测试不重叠程度、视图适配与保留手工布局的产品行为。

## 替代品与不选原因

ELK 有更多布局选项但配置面更大；力导向适合网络探索却增加运行过程和位置稳定性问题。Dagre 对第一版的有界知识图足够。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
