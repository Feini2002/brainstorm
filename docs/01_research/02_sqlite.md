# Node SQLite：优势、复用颗粒度与装配边界


## 采用结论

已选：唯一领域存储。本文将上游公开能力与本项目设计分开；来源索引：S04 S05 S06 S07，见 [来源登记](00_sources.md)。下述装配规则是项目要求，不表示上游库会自动替我们实现。

## 值得复用的具体优势

SQLite 把笔记、标签、关系、视图与运行记录放在一个事务数据库中，无需安装数据库服务器。Node 内置模块进一步减少第三方原生扩展安装链，对本机小规模 MVP 有实际价值。

## 组件怎么接入

通过 DatabaseFactory 取得按绝对路径缓存的连接；运行时惰性创建数据目录；设置外键、WAL 和 busy_timeout；所有用户文本使用绑定参数。Repository 只提供明确业务查询，不向页面暴露执行任意 SQL 的能力。

## 不能让车轮子替我们决定的内容

DatabaseSync 是同步接口，长查询会阻塞当前事件循环。WAL 不意味着任意多进程写入都安全顺畅，也不是备份策略。内置模块在所核验的 Node 24 文档里为发布候选，应保留 Repository 边界与实际升级测试。

## 输入、输出和所有权

输入是已经校验的领域值和期望版本；输出是纯 DTO 或明确领域错误。BEGIN IMMEDIATE 只包裹短写操作，永远不跨越模型网络请求。

## 最小集成实验

在临时文件库里测试事务回滚、外键级联、唯一幂等键、两个连接的竞争与重启持久化。用内存库通过测试不足以证明真实文件锁和 WAL 行为正确。

## 替代品与不选原因

better-sqlite3 是未来内置模块兼容受阻时可评估的替换，不作为默认双实现。PostgreSQL 与托管数据库目前只增加部署成本；不要为了未来可能多人使用提前搬走本地数据。

## 依赖治理

初始化时记录包名、精确安装版本、许可文件位置、是否包含原生二进制、是否需要浏览器环境、是否可能联网。提交 package-lock.json。后续升级只允许在独立变更中进行，并重复本组件的集成实验；不允许为修复一个报错同时把所有依赖升级到 latest。

如果实现与锁定版本文档不符，应记录实际 API 与最小复现，修正对应适配层。禁止直接 fork 整个上游仓库放进本项目，再靠手工编辑 node_modules 避开错误。只有无法通过公开 API 解决且得到明确架构变更记录时，才讨论替换组件。
