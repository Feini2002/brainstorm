    10|## 一、键盘可达（R04）

要求是「录入、导航、详情、审核、导出都只用键盘可以完成」。落点与验法：

| 能力 | 实现位置 | 自动化证据 |
| --- | --- | --- |
| 录入 | `CaptureBox`：输入框 + 「只保存」/「保存并整理」，`Ctrl+Enter` 直接保存 | T082-C04 在 150% 字号下聚焦 `capture-save` 并真的按 `Ctrl+Enter` 存下一条 |
| 导航 | `AppShell` 的 `<nav aria-label="主导航">`，六个页面都是普通链接 | T082-C04 每页先断言导航可见；T078-C05 窄屏下打开导航 |
| 详情 | `KnowledgeDrawer` 打开后焦点进入抽屉，`drawer-close` 可关闭 | T082-C06 从检查器打开抽屉再关闭 |
| 审核 | `RelationReviewPanel`、`GraphInspector` 的确认/拒绝是真实按钮 | T082-C06 用 `focus()` + `Enter` 从关系列表进入检查器 |
| 导出 | `ExportMindmap` / `ExportFlow` 的按钮在 `role="status"` 区域内 | T082-C04（导出所属页面的关键控件） |

### 模态抽屉的三条硬要求（T082 查出真实缺陷后补上）

`KnowledgeDrawer` 一直是 `role="dialog"` + `aria-modal="true"`，但**直到 T082 才开始管理键盘**：
在此之前它从不把焦点移入，也没有焦点陷阱，而 `aria-modal="true"` 会向读屏软件宣告「这是模态、
外面的内容不可交互」。结果是宣告与事实相反——焦点留在遮罩下面的卡片按钮上，之后每次 Tab 都在
背景页面里游走，数到「关闭」要按的次数比抽屉里的可聚焦控件还多。

现在这三件事都是必需的，缺一件就不是模态：

| 要求 | 实现 | 断言 |
| --- | --- | --- |
| 打开时焦点移入 | 焦点落到 `drawer-close`（抽屉里唯一恒在的控件） | T082-C04b：`抽屉声明了 aria-modal，焦点就必须进来` |
| Tab 不逃出面板 | `onKeyDown` 在面板内的首尾可聚焦元素之间回卷 | T082-C04b：连按 Tab 后焦点仍在抽屉内 |
| 关闭后焦点归还 | 归还给**打开抽屉的那个元素**，不是归还给 `<body>` | T082-C04b：关闭后焦点回到原控件 |

归还那条最容易写错，实际也真的写错过一次：**「记住打开者」的 effect 必须声明在「把焦点移入」
之前**。反过来声明时，它记下的是刚刚被聚焦的关闭按钮，抽屉卸载后该节点已不在文档里，
归还时焦点落到 `<body>`——键盘路径一去不回。这段顺序在 `KnowledgeDrawer.tsx` 的注释里标明是承重的，
`T082-C04b` 专测它。

**新增模态前请对照这三条**；只写 `aria-modal` 而没有陷阱，比不写更糟。

焦点本身有一处全局约定：`src/app/globals.css:77` 用
`:where(a, button, input, textarea, select, [tabindex]):focus-visible` 给所有可交互元素
一个统一的 `2px` 外描边。写这条是为了避免「某个页面自己写了焦点样式、另一个页面没有」
——`:where()` 的优先级为 0，任何组件仍可覆写它，但默认是可看见的。

**焦点顺序的两处有意相反**（详见 [copybook 第五节](./copybook.md)）：删除条目确认框把焦点
放在「确认删除」上，删除视图确认框把焦点放在「取消」上。这不是风格差异——删视图的入口就在
用户正在浏览的列表旁边，一个本来想按「打开」的 Enter 不该把视图删掉。

## 二、文本替代（R04）

「图本身有文本替代」的落点不是一句 `alt`，而是**一条可以走完的路**：不碰画布也能核对材料。

    30|- **关系图**：`GraphSummary` 的 `graph-relation-list` 是 `<details>`，逐条列出关系；
  `graph-alt-summary-nodes` / `graph-alt-summary-edges` 用文字报出「节点 N 个、关系 M 条」，
  所以数量不靠数图形得到。列表项的端点按钮打开的是真实记录抽屉。
- **脑图**：`MindmapOutline` 与画布**并列**渲染，而不是「画布失败时才出现」；每个节点写明
  「分组 · N 条来源」或「N 条来源」，选中后 `SourceList` 给出原文入口。
- **流程图**：`FlowSourcePanel` 列出材料与端点。

T082-C06 的两条用例分别证明这两条路：

- 关系图版：从 `graph-relation-list` → `graph-inspector` → `knowledge-drawer`，全程只用键盘，
  画布一次都没碰。列表若是装饰，这条路走不到抽屉。
- 脑图版：`mindmap-outline` → `mindmap-outline-select` → `source-list` → `knowledge-drawer`。
  折叠切换用 `aria-expanded` 暴露状态，且断言了「折叠真的收起子节点、展开真的放回来」，
  而不是只检查属性值变了。

线型与颜色之外还有文字：边标签里写着「待确认 / 依据已变化 / 端点已删除」，图例也重复了
这三个词。颜色是辅助，不是唯一载体。

## 三、动态状态如何被读出来

    50|等待与结果是两类不同的宣告，混用会让读屏用户听到错误的紧迫程度：

| 角色 | 用途 | 例子 |
| --- | --- | --- |
| `role="status"`（`aria-live="polite"`） | 动作进行中、动作已完成 | `LoadingIndicator`、`save-phase`、`view-freshness-banner`、`mindmap-outline` |
| `role="alert"` | 需要立刻知道且要处理 | `InlineError`、`ConnectionNotice`（本地服务未响应）、各页 `*-open-error` |

保存与整理是**两个**状态位而不是一个：`save-phase` 先报「已保存」，`organize-status` 再报
整理结果。所以「原文已保存，但整理没完成」不会覆盖掉「已保存」这条消息——T082-C01 断言的
正是这个顺序，并且顺带断言了失败之后原文仍然能按文本从 API 读回。

## 四、字号放大与固定像素（R06）

`tests/e2e/a11y-and-copy.spec.ts` 的 T082-C04 把根字号改成 `150% !important`，然后在六个页面
各选一个关键控件，断言三件事：

1. 它**完整落在视口内**，且中心点的 `document.elementFromPoint` 命中它自己或它的子节点
   （即没有被吸顶头部之类的元素压住）；
2. 它**可操作**（不是禁用状态）；
3. 它**能被键盘聚焦**，且按一次 `Tab` 后焦点真的离开了它（说明这个控件没有吞掉键盘）。

三个细节值得写下来，因为少了任何一个，用例都会变成「看起来绿、其实什么都没测」：

- **`boundingBox()` 不知道「被盖住」。** 一个被别的元素压住的按钮照样返回一个漂亮的矩形。
  遮挡正是 R06 里「固定像素布局容易遮挡文字」的那一条，所以这里额外做命中测试。
- **`addStyleTag` 在整页导航后失效。** 六页都是真导航，样式只注一次的话只有第一页是放大的，
  而后面的几何断言会在 100% 下通过。因此每次 `page.goto()` 之后都重新注入，并断言根字号
  真的大于 16px——「注入了但被别的规则盖掉」也必须红。
- **禁用控件不接受焦点。** 无选中材料时「生成脑图」是禁用的，`focus()` 会静默无效，断言读到
  的是上一个控件并报出一个误导性的原因。因此这一页先断言控件的可操作状态，再谈焦点。

## 五、没有验证的部分（如实单列）

以下四项**没有**做，不能从本文件推断为已通过：

    80|1. **屏幕阅读器人工检查（NVDA / VoiceOver / TalkBack）未做。** 本文件的角色与 `aria-*` 结论
   全部来自 DOM 属性与自动化断言，没有一次真人听读。
2. **浏览器之外的 150% 未测。** 操作系统级 DPI 缩放（Windows 显示设置 150%）与浏览器缩放
   是两条不同的通道，这里只覆盖了后者；前者未测。
3. **真实输入法候选窗未在无头浏览器里复现。** 中文输入法的组合态（composition）只有自动化
   层面的断言（T078-C05 的一部分），真实候选窗交互未测。
4. **对比度未按 WCAG 逐项计算。** 颜色都是既有设计变量（`--ink` / `--ink-muted` / `--warn-ink`
   等），没有做过逐组合的对比度测量，也没有做色盲模拟。

前两项与第四项属于人工验收，若要在发布材料里声称无障碍达标，必须先补上；
第三项受限于无头环境，只能在真机上补。
