# 产品总契约：这个系统到底应该是什么


## 一、交付目标

Feini Brain 是一个单用户、本机运行、能够保存与整理短文本的知识碎片系统。用户输入可以只有一个词，也可以是一句观点、一段论证或一个问题。保存不要求标题、目录、标签或 API Key。系统先把原始材料落盘，再在用户授权后请求外部模型生成可修改的整理结果。

“知识”在本产品里是用户保存的材料和观点，不意味着材料已经经过事实核验。GPT 的一句回答、个人推测、书中引文都可能被保存。系统必须区分来源、原文、摘要、模型推断和用户确认，不能把渲染出来的漂亮关系图当成内容为真的证明。

第一版的核心闭环是：输入不丢失；整理可追溯；关系可纠正；同一批材料能用卡片、关系图、脑图和流程视图观察；退出程序后数据仍在；导出后能够在空库恢复。完成这个闭环比拥有更多画布按钮更重要。

## 二、最低可用系统与范围控制

六个主页面固定为 Inbox、Library、Graph、Mindmap、Flow、Settings。Inbox 是采集动作，不是另一套数据库；Library 是知识实体的操作入口；三个可视化页面都读取相同实体和关系；Settings 管理模型连接与数据备份。没有仪表盘、用户注册、权限系统、团队空间、云同步、浏览器插件、文件上传和后台自动爬虫。

本地模式意味着 SQLite 和密钥保存在用户电脑，不意味着外部模型整理不联网。第一次启用模型时必须显示将发送哪些内容：当前条目、经过选择的候选摘要，或用户主动选择的视图材料。模型服务提供者能接触这些被提交的内容，其处理政策不由本系统保证。保存、查找、手动编辑、浏览已保存视图和导出不依赖模型在线。

不实现完整富文本编辑器。原文使用 textarea 和安全的纯文本展示。用户记录一词一语时，复杂编辑器的块模型、协同状态和格式菜单带来的负担大于收益。未来可以替换编辑器，但不能让编辑器格式成为唯一的知识存储方式。

## 三、为什么不是把几个应用嵌在一起

把 Memos、AFFiNE、Obsidian 和白板分别部署，再放入不同 iframe，会得到多个账户、多个存储模型和多个搜索入口。它们之间没有天然的一致主键，也无法可靠判断一张脑图引用的是哪一次笔记版本。这样的拼装外观看起来完整，数据治理却仍由用户手工承担。

本方案只复用组件层的能力：Next.js 作为宿主与本机 API；SQLite 保存领域数据；Zod 校验边界；React Flow 实现关系交互；Dagre 计算节点位置；Markmap 转换与呈现层级；Mermaid 呈现受限流程；DOMPurify 处理必要的非 React 文本渲染边界。我们自己实现的是领域契约、适配器、整理流程与证据关系。

这里的“一个系统”由统一 ID、共同状态、共同错误协议、共同来源入口和共同数据恢复机制定义，而不是由六个页面使用相同背景颜色定义。

## 四、用户可观察的功能要求

一条记录必须有不可变的 capturedText，代表最初提交的材料；还要有可编辑的 rawText，代表用户当前希望系统整理的版本。二者初始相同。用户修正错字时只修改 rawText，并增加 rawVersion，不会悄悄改掉最初保存的来源。MVP 不保留每一次中间原文版本的完整正文，但保留初始材料及当前版本，这一限制要在导出说明里写清楚。

标题、摘要、类型、关键词和标签是整理字段。用户手动修改后，对应字段加入 manualFields，后续 AI 整理默认不能覆盖。原文变化以后，旧摘要仍可显示，但标记为待重新整理；不能为了“干净”把上次可用结果清空。只有用户明确选择重置某字段，AI 才重新接管它。

关系同时有来源和审核状态。AI 生成的边默认是 suggested；用户可以接受或拒绝；手动创建的边直接 accepted。Graph 必须能区分建议与已确认关系。所谓 score 只是模型用于排序和筛选的启发式数值，不是正确概率。零条关系是合法成功结果。

脑图展示主题层级；关系图展示条目之间的关联；流程图展示有依据的顺序、依赖或显式标注的假设。三者不是一个万能图的皮肤。源条目修改后，已保存视图变为 stale 并提示重新生成，不能偷偷同步改写生成时的结论。

## 五、产品非目标

不承诺模型对每条笔记都能正确归类。不承诺自动找到所有跨月的隐含关联。不承诺一个 API Key 可以通用访问所有厂商模型。不承诺离线产生新的 AI 摘要。不承诺抗御已经控制用户操作系统的攻击者。

这些边界不是缺陷掩饰，而是可执行范围。第一版应该把不能确定的东西标出来，让用户能够查看原文、人工修改、重试与备份。一个承认结果不确定但不丢资料的系统，比一个把所有内容自动连线却无法纠错的系统更有价值。

## 六、验收定义

开发验收分为三个层次。确定性验收使用固定输入与测试替身验证数据库、接口和渲染；集成验收在实际锁定依赖中跑浏览器与生产构建；真实模型验收需要用户自己配置可用连接，验证一个词、相关观点、无关观点、矛盾观点和恶意指令样本。

没有真实 Key 时可以通过前两个层次，但最终报告必须把第三层列为未执行，不能拿固定返回值冒充真实模型已经工作。任何验收都不要求模型必须造出一条关系，不要求每次生成完全相同文字，也不要求内容效果达到未经定义的“智能”标准。
