# 测试覆盖映射｜规则 → 实际测试入口 → 真实缺口

本文件是 **T076 的必交产物**，回答一个问题：**每条测试规则由哪些文件、哪些断言真正守住，
以及哪里其实没守住**。它不是成绩单：第 4 节列的是没覆盖或覆盖得不够的地方。

数字来自本机实测（2026-09-16，T076 交付后）。命令与退出码见
[evidence/G6.md](../../implementation/progress/evidence/G6.md)。

## 1. 权威计数与运行方式

```
npm test                     81 文件 / 1054 例   exit 0
  ├─ unit        (31 文件)     392 例
  ├─ integration (38 文件)     517 例
  ├─ security    ( 8 文件)     103 例
  ├─ contracts   ( 3 文件)      32 例
  └─ browser     ( 1 文件)      10 例   ← 真 Chromium（T065/T066 的渲染安全）
npx playwright test          119 passed / 1 skipped   exit 0
```

**project 划分的效果**：`unit` 是唯一挂了网络守卫的 project（第 3 节 C06），
`integration`/`security` 需要真实 HTTP 与真实 SQLite，`browser` 需要真 Chromium。
各 project 单独跑的例数相加正好等于整跑（392+517+103+32+10 = 1054），
**以 `npm test` 整跑的数字为准**——单个 project 的 glob 若被改坏，先变的是这个总和。

覆盖率数字只作参考，**不替代业务断言**（T076-R01）：本文件第 3 节逐条给出的是
「这条规则靠什么断言守住」，而不是行覆盖率。

## 2. 测试层次与它们的证明力

| 层次 | 能证明什么 | **不能**证明什么 |
| --- | --- | --- |
| `tests/unit`（纯函数） | 边界、枚举、规范化、哈希在**输入层面**的行为 | 数据库约束是否挡住同一件事；浏览器里是否真的这样渲染 |
| `tests/integration`（真 SQLite） | 事务、外键、CHECK 约束、迁移、真实 HTTP 路由 | 布局与视觉；真实模型的语义质量 |
| `tests/security` | 跨站矩阵、秘密全链、出站边界 | 同机已入侵的进程（见 `docs/security-checklist.md` 第四节） |
| `tests/contracts` | 契约一致（limits 双登记、架构边界、暂挂路由） | 运行时行为 |
| `tests/browser` + `tests/e2e` | 真实 Chromium 的渲染结果与交互 | 领域校验（浏览器报错不是校验方案，T076-C03） |

截图、数据库断言、请求计数证明**不同的事**，不能相互替代。

## 3. 六条规则 → 实际入口

### T076-R01 每个公共纯函数都有正常、边界和反例

`tests/unit/` 共 31 文件 392 例。本轮补了两块**此前为零公共覆盖**的真空：

| 模块 | 之前 | 现在 |
| --- | --- | --- |
| `src/domain/evidence.ts`（4 个公共函数） | **零引用** | `tests/unit/evidence-contract.test.ts` 15 例 |
| `src/domain/text.ts` 的计数单位区分 | 只有 `'标'`/`'k'` 这类**不分叉**的样例 | `tests/unit/text-boundaries.test.ts` 6 例（用辅助平面字符分叉） |

其余模块（`hash` / `endpointPolicy` / `compileFlow` / `compileMindmap` / `structuredOutput` /
`redaction` 等）在此前 Gate 已有正常+边界+反例三组，本轮未重复。

### T076-R02 字符边界含中文、emoji、组合字符和空白；区分码点与 UTF-8 字节

守这条的是 `tests/unit/text-boundaries.test.ts`（6 例）+ 既有的
`capture-draft` / `timeline-cards` / `structured-output`。

关键点：`'标'` 是 **1 码点 / 1 个 UTF-16 单元 / 3 字节**，`'k'` 三者都是 1，
所以它们**无法**在"码点 vs UTF-16 单元"上分叉。本文件用辅助平面字符
（`'🧠'` = 1 码点 / 2 单元 / 4 字节）和组合字符（`'e\u0301'` = 2 码点）钉住契约单位。

**变异证据**（把 `codePointLength` 换成 `text.length`）：新矩阵 6 例红 5 例；
而既有 41 例的 unit 套件（capture-draft + structured-output + llm-config）只红 1 例。

### T076-R03 关系方向、对称规范化、拒绝保护和来源版本必须有明确断言

- **对称规范化**：`tests/unit/evidence-contract.test.ts` 的 `T076-C02` 一组。
  核心断言是「交换端点时各自的 `rawVersion` 必须**成对**跟着走」——只换 id 不换版本
  会把引用挂到错误的版本上，于是"编辑了 A"会让挂在 B 上的引用看起来过期或恰好相反。
  同时覆盖**非对称**类型（`causes` / `depends_on` 等）**不得**被排序，
  否则「A 导致 B」会被改写成「B 导致 A」。
- **拒绝保护**：同一文件的 `verifyEvidence` 一组，逐条覆盖
  `quote_not_found` / `quote_empty` / `unknown_item` / `wrong_endpoint`，
  并断言失败分支上**根本没有** `evidence` 字段可读（判别式结果的意义）。
- **来源版本**：`tests/unit/source-hash.test.ts` 的 `T076-C04` 一组。

**变异证据**：把交换改成"只换 id 不换版本"→ 红 1 例；让非对称类型也被排序 → 红 3 例。

### T076-R04 树结构覆盖环、孤点、深度、重复 ID；Flow 覆盖悬空端点与因果类型

此规则**在本任务之前已由上游任务充分覆盖**，本轮不重复实现（重复会让同一条规则
有两份实现，其中一份必然漂移）：

| 结构反例 | 入口 |
| --- | --- |
| 环、纯环、自指父节点 | `tests/unit/mindmap-compiler.test.ts`（`T056-C01`） |
| 悬空父节点、不可达子树、多根 | 同上（`T056-C03`/`C02`） |
| 深度 5 过 / 6 拒、节点数上限 | 同上（`T056-C05`、`T056-C01`） |
| 悬空端点、自环、重复 id | `tests/unit/flow-compiler.test.ts`（`T064-C03`） |
| 因果类型不被伪装成关联 | 同上（`T064-C04`） |
| 有依据的环**被保留**（不为变 DAG 删材料） | 同上（`T064-C05`） |

契约要求「在渲染前拒绝」：这些断言全部是纯函数调用，不经过浏览器——
**浏览器错误不是领域校验方案**。

### T076-R05 哈希排序稳定、输入改变敏感、生成时间不混入指纹

守这条的是 `tests/unit/source-hash.test.ts`（12 例）+ `tests/unit/hash.test.ts`。

本轮**加固了一处偶发守卫**：原「哈希不含随机字段」用例在同一瞬间调用两次，
一个毫秒级时间戳只有在两次调用恰好跨过毫秒边界时才会让它失败。

**实测（把 `Date.now()` 掺进指纹的变异下各跑 12 次）**：旧用例放行 **5 次**、
本轮新增的假时钟用例（把环境时间整体推后一天）放行 **0 次**。
偶发的守卫比不做守卫更危险——代码坏了它有一半机会说「没事」。
假时钟版同时更快：单个文件从 3.42s 降到 1.10s（实际测试 7ms）。

### T076-R06 固定随机种子与时钟，失败能稳定复现，不访问真实网络或用户数据库

两部分：

1. **不访问用户数据库 / 可用 Key**：由各 Gate 既有隔离保证（`BRAIN_DATA_DIR` 指向
   每次运行独立的临时目录），`tests/e2e/support/resetData.ts` 另有明确重置。
2. **不访问真实网络**：本轮**新增强制装置**（此前只有约定）——
   `tests/unit/support/networkGuard.ts` 挂在 `unit` project 的 `setupFiles` 上，
   对非回环主机的 `fetch` 与 `net.Socket.connect` 直接抛错，回环放行（同进程临时服务器、
   端口探测仍可用）。这不是防御机制而是测试装置：它让 C06 的结论**被强制**而非靠自觉。

**这条装置自己也出过一次真实缺陷**：`connectHost` 收到了 `[[options, cb]]`（Node
`net.connect` 会再套一层），导致主机读不出来、**所有回环连接一起被拒**。
fail-closed 方向没错，但会打断测试装置自己的 helper。是 `T076-C06` 的回环用例把它抓出来的。

**接线必须单独钉**：本文件的测试模块 `import` 了守卫，而导入会执行其顶层副作用，
所以即使 `setupFiles` 被摘掉，该文件仍 6/6 绿——但**其它** 30 个单测文件就全部失去保护了。
因此另加一条读 `vitest.config.ts` 的断言；实测摘掉 `setupFiles` 后只有这一条变红。

## 4. 未覆盖 / 覆盖不足（如实列出）

- **没有覆盖率百分比**。本轮没有接入覆盖率工具，也没有用行覆盖率替代业务断言。
  本文件的映射是**规则级**的：某模块"有测试"不等于它的每个分支都被断言过。
- **`start-local` 会真 spawn 子进程**（`tests/unit/start-local.test.ts`），
  所以 `unit` 在"网络"上是 fail-closed，在"子进程"上不是。若将来有单测真的去连外网，
  守卫会拦住 `fetch`/TCP，但拦不住子进程自己发起的连接。
- **`0.0.0.0` 在守卫里被当作回环放行**：它本身不是"某台外部主机"，而单元测试里唯一
  会用到它的场景是同进程服务器绑定通配地址。这是一个有意的宽限，不是疏漏。
- **组合字符（`'e\u0301'`）只断言了计数**，没有覆盖"按字素簇截断"——契约明确按码点算，
  所以"视觉上一个字被截成两个"这件事**不在**本工具的处理范围内。
- **没有真实模型语义用例**：`BLOCKED_BY_EXTERNAL_CREDENTIAL`（与 G2/G5 相同）。
  这是设计而非缺口：本任务的六条规则全部是确定性规则，不需要模型。
- **`tests/contracts/semantic-cases.test.ts`** 是 T042 的**契约层**用例（14 例，
  断言 fixture 结构与分支覆盖），它证明的是"用例集本身完整"，
  **不**证明真实模型的语义质量。

## 5. 维护约定

1. **同一条规则只有一个家**。本轮把 `src/domain/evidence.ts` 与 `text.ts` 的边界补进来时
   没有另建平行套件；T075 也是把散落的 T007/T030 断言**移动**（git 记 `R`）到
   `tests/security/`，不是复制。
2. **新增 project 或改目录 glob 后，必须核对全量例数是增是减**：
   移到没人收集的目录会**静默不跑**，不报错。
3. **改动 `src/domain/text.ts`、`evidence.ts`、`sourceSnapshot.ts` 前先跑对应变异对照**
   （第 3 节给了可复现的破坏点），否则新增的边界断言可能只是复述实现。
4. **不要把偶发守卫当守卫**：测得放行率不为 0 的断言（如第 R05 节那条旧用例）
   要替换成确定性的，而不是加一个 `retry`。
