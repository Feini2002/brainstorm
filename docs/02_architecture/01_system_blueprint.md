# 系统蓝图：组件如何真正装配为一个产品


## 一、四个平面

系统分成领域数据平面、交互呈现平面、模型处理平面和本地运行平面。领域平面只有 Item、Relation、View、Run、Settings 等少量模型；交互平面不直接认识 SQL；模型平面只接受经过裁剪的 DTO；运行平面负责本机监听、数据目录、日志、安全令牌和生命周期。

请求从 React 页面进入同源 API，经本地请求保护与 Zod 验证后到达应用服务。应用服务调用 Repository 完成数据库事务，或调用 LLM Adapter 完成外部请求。Renderer 只能读纯 JSON，不允许导入数据库、密钥或远端模型客户端。Graph 拖动节点只保存位置，不能改变笔记正文。

目录边界固定为 `src/domain`、`src/server`、`src/features`、`src/components`、`src/app`。domain 放跨前后端共享的纯类型与校验，不引用浏览器或 Node 专属 API；server 显式引入 server-only 防止进入浏览器包；features 对应六个用户场景；app 只做路由与装配。

## 二、保存与整理的真实顺序

用户点击保存，浏览器先生成 captureRequestId 并将当前文本放入请求。服务端在事务中插入条目、建立请求指纹、增加 datasetRevision，然后返回数据库认可的 ID。只有收到保存成功，输入框才清空。网络响应丢失时使用相同 captureRequestId 重试，必须得到同一条目，而不是重复插入。

保存并整理是两个独立操作的顺序组合。第二步整理失败不能回滚第一步保存。UI 显示“已保存，整理失败”，而不是“保存失败”。浏览器重新打开后也应从数据库查到原文与整理状态。

整理请求注册持久化 Run，并用数据库条件更新确保同一个 Item 没有两个有效运行。注册事务必须短暂结束，再发模型请求；模型响应返回后开第二个短事务，重新检查 Run 状态、条目 revision 与 rawVersion。只有快照仍然匹配才提交元数据及关系，否则把 Run 置为 conflict，不覆盖用户刚做的编辑。

不在数据库事务里 await 网络。也不在返回 HTTP 之后启动一个没有生命周期保障的悬空 Promise。MVP 的操作请求一直等待到完成；同一页面可同时轮询只读 Run 状态，但没有独立工作进程、消息队列或可靠离线任务承诺。应用重启后，过期运行标记 interrupted，用户手动决定是否重试。

## 三、关系与候选检索

最近四十条并不是完整的相关性检索。第一版采用轻量混合候选：最近十二条保证新内容覆盖，其余名额通过标题、摘要、原文检索片段、标签的字面匹配与关键词命中取得；合并去重后最多四十条。中文采用规范化子串匹配及受限二元片段策略，不依赖空格分词，也不把 SQL LIKE 宣传成语义检索。

候选排序必须可解释与可重复，记录候选 ID 和算法版本。传给模型的候选摘要逐条限长，总上下文再限长。这个上限只是本项目预算，不是模型最大上下文承诺。来源较老却字面相近的条目能被找回；只有隐含同义而没有任何重叠时仍可能漏检，这部分后续由语义检索解决。

模型只能引用本次候选集中的目标 ID。关系类型与方向由契约固定，所有证据摘录都要在相应 rawText 中逐字匹配。不存在的 ID、无依据的摘录和越界分数都不进入关系表。拒绝的建议保留记录，重新整理不能复活它。

## 四、三个 Renderer 的组合

Graph Adapter 从知识实体和有效关系生成 React Flow nodes/edges；自定义节点显示标题和标签，边显示关系含义与建议状态。Dagre 输入固定节点尺寸和边，输出坐标；适配器将中心坐标转换为 React Flow 左上角坐标。用户移动后的坐标保存在 View，不写回 Item。

Mindmap Service 要求模型返回受限的层级 JSON，而不是任意 Markdown。服务端检查唯一根、父子连通、深度、节点数、来源 ID，再把标签编译为受限 Markdown。浏览器使用 Markmap Transformer 和 Markmap View。需要 HTML 的标签内容必须经过净化，禁止自动加载远端脚本、数学插件或模型提供的资源链接。

Flow Service 同样要求受限的节点和边 JSON。程序用受控模板生成 Mermaid flowchart 语法。模型不能提交 click、初始化配置、脚本、外部链接、任意 HTML 或直接 SVG。Mermaid 的 strict 安全配置与 SVG 净化是第二层防护；第一层是只让模型提供数据，而不是程序。

两个生成视图都保存被引用的条目 ID、rawVersion、revision、生成哈希、提示词版本和模型配置摘要。用户查看来源时，通过旁边的来源面板打开真实条目。生成结果不是可反向编辑的知识库，不允许脑图拖动顺手变更原文。

## 五、缓存与性能边界

本地业务 API 使用 no-store；不使用框架共享缓存保存私人知识；LLM 请求也不能使用可复用的响应缓存。浏览器只保留当前页面状态，修改后按明确数据影响表刷新，不设置全站常驻轮询。只有运行中的 Run 使用短暂轮询，终态、隐藏页面和卸载都停止。

图表代码按页面动态导入，Inbox 与 Library 初始包不加载 Mermaid、Markmap 或 React Flow。第一版 Graph 最多显示二百节点、六百边；超限必须提示筛选，不静默丢节点。脑图和流程先限制来源条目数，再限制模型输出图规模，以避免一个坏返回值冻结浏览器。

## 六、运行拓扑

只有一个 Node 进程负责 API 与 SQLite。开发使用 Next dev，日常使用完成 build 后的 Next start。两者明确绑定 127.0.0.1。不同时启动两个应用进程写同一数据目录，不放在网盘同步目录，不直接部署到无持久磁盘的函数平台。

数据库初始化通过运行时函数惰性进行，不在模块导入时创建数据库，不在 build 时触发迁移。测试用临时目录，生产数据默认 `.data/brain.db`；BUILD、TEST、DEV、USER 四种模式必须能在诊断信息中分辨。诊断接口不得返回 API Key、绝对私人路径或完整笔记。
