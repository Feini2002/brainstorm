每条给出四要素：**怎么复现**、**影响是什么**、**现在怎么绕**、**是否阻塞发布**。
「不阻塞」不等于「不用管」——它表示这条不影响"原文不丢、无秘密泄露、无静默覆盖、可恢复"
四条硬性不变量（判定依据见 [acceptance-report.md](./acceptance-report.md) 第 10 节）。

## 1. 阻塞发布

**无。** 当前没有任何一条已知问题落在"必须修好才允许发布"的类别里。

但有一条**阻塞结论**，性质不是缺陷而是缺凭据：

### 1.1 T042 真实模型语义验收从未跑过（阻塞结论，不阻塞产品可用性）

| 项 | 内容 |
| --- | --- |
| **复现** | 不配置 API Key，直接 `POST /api/items/{id}/organize`，或读 `implementation/progress/evidence/G2.md` 的语义组 |
| **现象** | 稳定返回 `422 MODEL_NOT_CONFIGURED`（确定的领域错误，不是 500）。语义组用例诚实 `skip`，没有被替身顶替 |
| **影响** | 能证明"AI 整理**按契约**接线正确"（结构层，替身 + 隔离集成测试覆盖），**不能**证明"整理得**好**"——标题、摘要、关键词、关系是否恰当，以及模型是否克制地不写无依据的因果，全部未验。凡是宣称"整理质量"的结论都缺证据 |
| **临时处理** | 由用户自己在设置页配置 Key，然后跑 `npx playwright test tests/e2e/gate2.spec.ts`；结果只能由那次真实运行写入 `evidence/G2.md`，不得用替身补 |
| **是否阻塞发布** | **阻塞该条结论**，不阻塞 G6。T070–T075 恰恰断言的是"没有模型配置也能导出""恢复不触发模型""不发起任何外部请求"，这些结论在无 Key 环境下是完整的。对外表述必须写成"离线闭环已验证，AI 语义质量未验" |

> **为什么不干脆用替身跑一遍记成通过**：替身能证明"按契约处理了响应"，不能证明"整理得好"。
> 把两者写成同一个数字，等于让交付材料里最需要可信的一项变成噪声。

## 2. 不阻塞，但用户会实际碰到

### 2.1 Playwright trace 会归档已提交的请求体（含明文 Key）

| 项 | 内容 |
| --- | --- |
| **复现** | 在 e2e 用例里往设置页的密码框填一个真 Key，跑完后解压 `test-results/**/trace.zip`，`network` 段里有明文 |
| **影响** | 产品侧三处（密码框、`GET /api/settings` 响应、导出字节）实测**均无明文**；泄露点是**测试装置**。跑过真实模型用例的开发机上，`test-results/` 会落盘明文，可能被误传或误提交 |
| **临时处理** | `test-results/` 与 `playwright-report/` 均在 `.gitignore` 内，且**从不进证据目录**；T083 新增的 `npm run status` 会把这两个路径列入禁止跟踪项并拦下。真实模型用例请只在本机跑，不要贴 trace |
| **是否阻塞发布** | 不阻塞。不影响运行中的应用，也不影响交付物（交付物里没有 trace） |

### 2.2 内容安全策略（CSP）未启用

| 项 | 内容 |
| --- | --- |
| **复现** | `npm start` 后看任意页面响应头：没有 `Content-Security-Policy` |
| **影响** | 少了一层缓解 XSS 纵深防御。已实测的补偿措施：Markmap/Mermaid 走 DOMPurify 净化、图标签攻击有专门回归（`tests/security/graph-label-attack.test.ts` 6 例）、外部资源不加载（`source-url-no-fetch.test.ts` 10 例） |
| **临时处理** | 没有。这是**有依据的设计缺口**，不是遗漏 |
| **为什么不直接打开** | Mermaid 依赖自己注入的内联 `<style>` 来配色，而净化合同要求留住 `#a{fill:#fff}` 这类惰性样式表。不留 `style-src` 空间的严格 CSP 会**直接破坏图形视图**。启用需先设计 Mermaid/Markmap 的样式策略（nonce 化注入，或把配色移到允许属性上），那是独立工作 |
| **是否阻断** | 不阻塞发布，但**不得在交付材料里声称已启用**。`docs/security-checklist.md` 如实写"未启用"，`tests/security/threat-model-honesty.test.ts` 15 例断言文档与代码都没有声称已启用 |

### 2.3 API Key 在本机明文存储

| 项 | 内容 |
| --- | --- |
| **复现** | 配置 Key 后，用任意 SQLite 客户端打开 `.data/brain.db`，`secrets` 表里就是明文；服务端的返回与日志都不含它 |
| **影响** | 这是本机单用户程序的有意设计：它必须把 Key 交给服务商使用，**没有**硬件级密钥保护。因此 `brain.db` **不是**可外发的诊断包，也不应被同步到网盘 |
| **临时处理** | 备份用应用内的逻辑导出（`GET /api/export` 或设置页），它按显式白名单列导出，**不含** Key、设置与运行记录；文件级复制 `brain.db` 前必须先停服（WAL 里最近的提交不在主文件中） |
| **是否阻塞发布** | 不阻塞。属已披露的产品边界，写进了 `README.md` 的"你的数据放在哪"表 |

### 2.4 日志只写进程标准输出，不落盘、不轮转

| 项 | 内容 |
| --- | --- |
| **复现** | 起服务后看工作目录：没有日志文件；诊断日志出现在终端里 |
| **影响** | 关掉终端就丢了历史；排查"昨天出问题"的场景缺少材料。好处是**不会**有日志文件无限增长、也不会把笔记内容写进磁盘 |
| **临时处理** | 需要留存时自行重定向：`npm start *> app.log`；"日志有界"由内存保留上限 + 重复限流两条界保证（T074-C04 实测） |
| **是否阻塞发布** | 不阻塞。要改成落盘轮转需新契约，不在实现里偷偷加 |

### 2.5 服务监听地址只允许回环，含 `0.0.0.0` 的有意宽限

| 项 | 内容 |
| --- | --- |
| **复现** | `APP_HOST=0.0.0.0` 时启动器仍只绑 `127.0.0.1`（`netstat` 里 `0.0.0.0:<port>` 条目数为 0，T081 实测）。唯一例外：守卫的判定逻辑把 `0.0.0.0` 当回环放行 |
| **影响** | 单机场景无影响；确实想局域网共享时**做不到**，且会明确被拦下而不是静默打开 |
| **临时处理** | 无。这是安全设计：同源检查依赖"监听地址 = 用户配置的地址"这一等式，放开它要重新设计 Host 判据 |
| **是否阻塞发布** | 不阻塞 |

## 4. 已修掉、留在此处供搜索命中的两类问题

这两类都曾经**实际发生**且**没有产生任何红灯**，因此值得留在已知问题清单里，
让后来搜索症状的人能找到答案（而不是重新踩一遍）。

### 4.1 已标 `verified` 的任务，证据指针断掉

- **症状**：报告里写着"见 `tests/integration/security-http.test.ts`"，但那个文件已经不在那里了。
- **发生过两次**：T075 把安全用例移到 `tests/security/`；T081 把 `vitest.config.ts` 改名为 `.mjs`。
  两处都只改了代码，没回头改 `tasks.current.json` 里的指针。
- **修法**：T083 新增 `npm run status`，逐条校验 evidence 路径存在性 + 锚点可定位性。
  这条检查现在是 `npm run check` 的一环。
- **教训**：文件改名/移动时，**搜索全仓库的引用**包括 `tasks.current.json` 与证据文档里的路径。

### 4.2 锚点写错，证据"看起来具体、指不到地方"

- **症状**：`evidence/G0.md#5-t007-本地请求令牌与来源防护可归属证据2026-09-15-复核`
  这条锚点任何渲染器都定位不到——标题里的空格没有转成连字符。
- **影响**：读报告的人点进去落到文件顶部，会以为"证据很薄"，而真实内容在第 74 行。
  比"没有锚点"更糟，因为它看起来更精确。
- **修法**：`npm run status` 按 GitHub 的锚点规则真实推导每个 markdown 的锚点集合并逐条核对；
  需要自定义锚点时显式写 `<a id="…">`（G4 的 T053–T061 就是这么做的，9 个锚点实测全部可定位）。
